# 织章：界面与交互

## 视觉方向

温暖但清晰的创作桌面：纸张色背景、深墨色正文、赤陶色主操作、雾蓝色辅助关系。视觉层次来自内容、留白与排版，而不是高饱和渐变和大量指标卡。

英文品牌可使用衬线字，正文保持中文系统字体。正式 UI 使用一致的间距、圆角、边线、选中状态和焦点样式；原型不依赖外部字体或图片。

## 页面结构

```text
┌─────────────┬──────────────────────────────────────────────────┐

│ 作品概览     │                                                  │
│ 卷章大纲     │             当前工作区                             │
│ 故事画布     │    内容区域为主体，侧栏跟随当前选中对象              │
│ 章节写作     │                                                  │
│ 人物与世界   │                                                  │
│ 审阅与版本   ├──────────────────────────────────────────────────┤
│ 导出         │ 版本／引用／当前操作结果                           │
└─────────────┴──────────────────────────────────────────────────┘
```

## 七个视图

### 作品概览

作品封面、简短意图、当前章节与一个继续按钮。帮助新手判断下一步，不用字数排行榜或虚构商业数据填满首页。

创建作品只需要标题与故事种子。题材和写作目标允许稍后补充。

### 卷章大纲

卷／章层级与章节目标。一个章节至少展示“推进什么、关键冲突、进入条件／转折”。章节可以直接跳转到对应画布或正文。

### 故事画布（特色主屏）

中央是情节结构，右侧是选中节点的目标、设定来源和关联章节。顶部给当前卷章范围，底部提供版本信息。

节点不只是“第几章”，还区分情节、动机、线索与伏笔；连线需表达依赖类型。节点选中后可以定位正文或发起建议，避免画布与正文变成两个孤立工具。

### 章节写作

编辑区承担细读和修改。AI建议位于侧栏或局部对照区，不覆盖正文。接受、拒绝、撤销与来源引用是关键动作。

正式版在编辑时显示保存状态、版本冲突和任务状态；原型仅提供本地示例编辑与建议。

### 人物与世界

人物卡、世界规则、伏笔采用局部标签切换。每张卡显示少量关键事实，细节按需展开。出处、确认状态和使用章节比“人物数量”更有价值。

### 审阅与版本

按问题类型或修改组查看。左侧原内容、右侧建议或新内容，下方列影响章节和设定。作者先判断，再确认，不接受一键覆盖整卷。

### 导出

正文与创作资产分别导出。Markdown用于阅读或继续编辑；资产 JSON 保留章节、设定、图结构和版本关联。正式应用需版本校验和导入预览。

## 交互与状态设计

| 场景 | 正式 UI 必須表现 | 本轮原型 |
|---|---|---|
| 空作品 | 一个故事种子输入与下一步，不强制填完整资料 | 创建与示例作品入口 |
| 任务处理中 | 取消、已保存输入、流式预览与明确状态 | 不模拟真实长任务 |
| 任务失败 | 保留正文、输入快照和重试入口 | 作为正式实现验收要求 |
| 来源过期 | 指出旧正文／旧设定版本 | 设计文档明确要求 |
| 接受建议 | 仅更改指定范围、保留可撤销版本 | 局部示例接受／撤销 |
| 设定修改 | 影响范围与用户确认 | 示例影响对照 |
| 窄屏 | 页面重排、可读文字、主要动作仍可访问 | 原型需浏览器检查 |

## 评审时建议看的四件事

1. 默认画布是否让人看得懂故事关系，而不是只觉得好看。
2. 从情节节点到正文，是否只需少量明确动作。
3. 编辑器中的 AI 是帮助修改，还是让作者失去控制。
4. 版本与导出是否给作者足够的数据安全感。

原型不是最终高保真定稿，用户可以就模块名称、信息密度和核心动线反馈；不需要先补一整份产品需求。
