# 织章：后续开发边界

## 设计与应用分离

`prototype/` 是可离线打开的体验参考，`docs/` 是当前设计基线。后续正式代码建议放到 `apps/web/` 与 `apps/server/`，不把原型本地状态直接迁移成正式领域模型。

本轮未生成正式应用骨架、DDL、模型凭据或部署资源。

## 推荐起步技术

| 层 | 推荐 | 原因与边界 |
|---|---|---|
| Web | Vue 3 + TypeScript + Vite | 与用户已有经验匹配，组件样式按本原型建立设计系统 |
| 节点画布 | Vue Flow | 节点语义与自定义样式贴合故事结构，采用前锁定版本和许可 |
| 编辑器 | Tiptap开源核心 | 结构化正文与扩展，云／Pro能力单独核查 |
| 服务端 | Spring Boot模块化单体 | 作品、版本、任务、建议分包；先保持单进程清楚的事务边界 |
| 数据 | MySQL，文件资产先受控本地存储 | 正文、图JSON、来源与版本可靠保存；备份优先 |
| AI | OpenAI-compatible适配接口＋任务快照 | 连接经用户授权的现有API，不依赖本地GPU |
| 任务状态 | 数据库任务＋SSE | 先保证中断恢复、幂等与结果保存，再扩并发 |

暂不默认引入向量库、MQ或一整套微服务。跨卷检索先使用作品内标签与关键词，只有明确出现检索质量或容量问题才验证其他方案。

## 依赖顺序与验收

### 阶段1：可以持续写的一本书

作品、大纲、正文编辑、确认设定、可靠保存、版本、导出。先证明关闭页面后能继续写。

### 阶段2：画布与正文真正联动

节点和连线编辑、关联章节、设定引用、定位正文、撤销。创建和删改节点不破坏历史版本。

### 阶段3：可控的AI建议

模型连接授权、上下文预览、生成任务、局部接受／拒绝、失败恢复、版本冲突。AI结果不直接覆盖正文。

### 阶段4：修改影响与一致性审阅

引用关系、规则检查、模型建议分开评价。用自拟样例检验误报、漏报与作者确认流程。

每阶段同时做可见UI与服务端闭环，不先做一整套“后端全完了、前端以后再说”的工程。

## 运行与测试基线

- 正式应用需要独立开发配置，密钥不进Git；后续实际配置不从旧项目自动拷贝。
- 核心测试：权限、版本冲突、局部接受、任务重试、存储失败、导入导出一致性。
- UI验收覆盖空态、保存中、失败、旧建议与正文冲突、窄屏；截图不是替代真实交互。
- 日志带taskId／workspaceId，不默认存完整敏感正文。

## 发布前条件

可靠备份与恢复、数据出口、访问权限、模型传输说明、版权与采用组件许可核查。产品不承诺作品收入；发布动作由作者单独确认。
