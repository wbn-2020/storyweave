## 拆书与卡片复用

拆书继续通过 AI 副驾驶的 `kind=plan`、`purpose=study` 完成，作者明确选择全局参考原文，先保存发送预览再请求模型。任务不发送当前章正文、作品创作约定或本书记忆。新提示版本为 9，旧提示及原始输出保留。

| 资产 | 当前保存内容 | 复用入口 |
| --- | --- | --- |
| 节拍骨架 `beat` | 分析、适用范围、复用限制，一至六个名称／行动／变化节拍 | 大纲页“套用全局节拍骨架”，确认载入表单，改为本书情节后保存新修订 |
| 文风卡 `style` | 分析、适用范围、限制、句式节奏、对白、感官偏好、措辞与动词 | 副驾驶“场景、资料与写作方法”中明确选入 |
| 技法与方法 | 原有 `technique`、`method` 文本卡 | 同一资料选择器，或复制至作品方法笔记 |
| 观察与摘录 | 原有 `observation`、`excerpt` 文本 | 保留固定来源与逐字引文 |

每个拆书项目仍须在对应固定参考原文中找到连续、逐字的引文，不能拼接或改写。参考 ID、修订和引文沿用现有来源记录，逐项采用沿用全局资料库的立即事务、不可变历史、容量与重复登记检查。结构化卡片正文存为 JSON，作者通过字段编辑器修改。

写作时只发送作者选中的卡片内容、适用范围与限制，不自动展开参考作品原文；提示要求借用抽象结构和表达技法，使用当前作品人物与地点。模型是否完成去名化、是否过度接近原参考，仍须作者审阅，当前没有语义相似度或原创性检测。

套用节拍会替换当前章纲表单中的节拍，必须先确认；保存继续核对作品版本、章纲版本和锁定状态。首次引用新卡片时核对全局条目的版本、标题、正文及归档状态。`OutlineFields.beatSource` 保存当时的完整卡片快照，随不可变大纲历史和单书恢复保留。来源卡后来修改，不自动改动已保存章纲；恢复旧纲使用其原始快照。

## 实稿语言提示与虚拟试读

“规划、审稿与写作记录”中的语言提示读取当前已保存的完整章节，执行固定套话词表匹配和同一段中连续三个相同代词句首的检查。命中附实际段落 ID、逐字片段与固定稿件修订；最多列出 120 处，并显示实际总命中数。换章或换稿后旧结果不可登记，需重新扫描。

词表命中不证明文本来源或质量，没有困惑度、AI 概率、过审、安全分或说明文语义占比测量。提示可登记为待判断问题；不会生成伪造的改写稿。

虚拟读者提供爽点与节奏、设定与因果、情绪与互动三个角度。选定后进入副驾驶的审稿任务，发送完整预览后才发起实际模型请求。界面不预填读者评论或评分。试读默认只带章稿及作者要求，不自动发送作品简介、前情摘要或全知设定；作者后续选入的资料以实际消息为准，不能据此宣称整体输入没有剧透。

## 结构化审稿与改稿

新审稿提示版本为 8，仍用 `kind=plan`、`purpose=review`，不增加网络会话。只允许完整本章上下文，超过预算时明确缩减资料或调整预算，不把裁剪片段当作完整段落替换。输出最多 24 项，每项保留角度、类别、理由、可能反证、修改方向和可选替换正文。

| 来源情况 | 校验与后续处理 |
| --- | --- |
| 正文问题 | 一至十二个按原顺序连续的非空文本段落；引文必须逐字存在于其中同一段。替换稿面向完整范围 |
| 缺失事项 | 作者明确选入有效章纲上下文；引用当前章的固定大纲修订及 `goal`／`conflict`／`hook` 字段完整值。正文定位、引文和替换稿均为空 |
| 历史普通文本候选 | 原文继续可读，可在审稿清单手工登记；不把旧输出猜测为新 JSON |

作者可以编辑理由、修改方向和替换稿，分别登记为待处理、忽略或刻意安排。`ReviewIssueFields.candidateSource` 保存原始候选项目、项目序号、候选版本和上下文指纹；首次正文基线和引文也保留。服务端重读固定任务并逐项比较，不能通过前端输入替换来源。同一任务项目只首次登记一次，重开面板从清单识别已有决定。

`suggestion` 表示分析性修改方向，新增可选 `replacement` 表示可直接写入的正文。旧问题没有该字段时保持原有建议正文的行为。新问题替换稿为空时不能进入正文替换。

登记、写入历史和推进作品版本在原有作品立即事务内完成。未知写入只查询原请求，保留作者表单和客户端 ID；登记已确认而父层同步失败时，只重读作品，单独保留并核对原同步读取编号，不重发登记。

副驾驶抽屉中的预设保存、审稿登记与正文输入可以交错。同步目录时，同一章节、同一正文修订仅更新章节元数据与作品版本，保留草稿、输入法状态、编辑器实例和恢复检查点身份；正文修订不同则提示作者刷新。目录和书架不接收较旧版本，正文保存回执也不回退已确认的作品版本或更新时间；没有新增正文修订的保存保留期间收到的较新元数据。

审稿清单可查看文字差异，先明确确认替换稿，再用当前作品、问题和正文版本核对后提交。写入产生新正文修订，并将问题转为待复核。缺失事项不能套用段落替换；章纲来源发生变化或待复核时，旧建议显示过时，不能直接标记为已解决。来源正文陈述、人物信念与模型推断仍由作者独立判断。

## 定稿记忆归档

归档沿用 M2 的发布机制，不另外写入知识实体或人物认知。新只读命令 `living.archive` 接入契约、参数校验、主进程白名单、服务分发和 preload；`listMemoryArchive` 支持按章节过滤，按创建时间与 ID 稳定分页，每页最多 20 批、8 MiB。

大纲与定稿记忆页默认载入最近批次；作者点击“查询所选章节的全部归档”后可翻阅历史页。状态与知识性质过滤作用于当前页，界面显示范围和总批次数。每条摘要、事件与状态继续展示固定定稿修订、段落和原文，区分当前有效、待复核和被替代的历史批次。

## 模型选择、用量与格式

本批复用每书任务预设：规划、续写、改写、审稿和拆书分别可设置一个未归档的默认预设，并绑定已保存模型连接。副驾驶“载入此任务的默认要求与模型”明确读取当前预设；已有要求会先提示替换，连接不可用时停止，不静默改用其他模型。实际发送仍绑定保存预览中的连接配置。演进沙盘、工坊和独立整理任务继续由各自表单显式选模型。

## 2026-11-13 模型列表探测

新增 `AiConnectionProbeInput`／`AiConnectionProbeResult` 和两个只在主进程处理的 renderer 命令 `connection.probe`／`connection.probe.cancel`，不扩展数据库服务命令或 schema。输入只能指定工作室／书籍范围、已存连接 ID、期望版本与请求 ID，不能注入临时 URL 或密钥。书籍先沿原连接读取链路核对迟到配置回执；主进程以小范围只读方法取得既有内存密钥，工作室复用原 `GenerationSessions.sessionKey`。

`ConnectionProbes` 使用 `GET <baseUrl>/models`，只在有效 JSON 模型列表含配置名称时成功。响应头耗时显示为连接延迟，不等同生成首 token 延迟或生成可用性。网络等待 8 秒、响应最多 1 MiB／10,000 项、不跟随重定向、不读取失败正文，返回固定中文原因。最多三个探测，同一范围与连接防重复；无生成任务、正文或存储写入。

探测拥有独立取消控制，不加入正文 dirty 或生成任务门禁。关闭、切库和服务恢复时中止探测；界面通过范围／版本／请求 ID 隔离迟到响应，刷新后取消旧版本请求，范围列表读取期间禁用标签。实际探测中原生关闭为 673 ms；8 秒挂起分支为 8,017 ms。

## 2026-11-13 正文采用撤销与失败重新准备

`App.tsx` 在正文采用前固定原章节快照，校验成功回执后显示写入状态及撤销入口。撤销复用 `revision.restore`：固定 `expectedRevisionId` 为采用后的修订，来源为采用前的原稿修订；回执须匹配作品、章节及原稿完整 document，然后推进正文和目录。恢复总是新建历史节点，不回滚 AI 作者决定，不移除采用稿或原定稿。根目录／作品／章节不符、有新草稿、输入法组合、归档或已推进修订时禁止直接撤销，保留版本历史入口；规划备注不走正文撤销。回执不确定时沿用原请求核对机制，不盲目重发。
