## 产品与工程边界

面向个人 Windows 电脑的本地小说工作室。作者选择作品目录，按章编辑与保存。每次正文保存形成可追溯版本；AI、检索与图谱依赖同一作品身份和来源版本。

源码覆盖选择书库、作品与卷章管理、正文编辑和版本保存，以及历史浏览、定稿、文本导入导出、章内查找替换、专注写作、草稿恢复、手工知识条目、作者维护的关系／事件／伏笔／人物认知记录、持久整理任务、本地关键词／实体检索，以及 D5 模型连接、上下文预览、规划／续写／改稿、完整单章摘要、知识抽取、作者审阅采用、持久逐章整理任务、卷／全书分层汇总、前文摘要选择、附加故事资料的读者披露资格、逐批向量索引和有界混合检索。具体静态检查记录见开发进度；人物知情与完整恢复包继续按计划实施。

## 一次保存的具体流程

以“打开第一章，修改两个段落”为例：

1. 界面载入该章的正文 JSON、段落 ID 和当前 revision。
2. 用户输入产生草稿；输入法组合结束后才安排自动保存。手动保存、切章、切书和关闭使用同一串行保存入口。
3. 命令携带作品、章节、预期 revision 和正文。主进程检查页面来源，业务进程校验结构，存储层再检查当前版本。
4. 正文 JSON、纯文本、内容 hash、新 revision、章节指针、作品修订号和 outbox 在书内同一事务中提交。
5. 成功回执才推进界面中的已保存版本。保存期间的新输入仍标为待保存，不用旧回执替换编辑器。
6. 超时视为结果未确认，通过请求回执查询恢复已完成结果；版本冲突保留草稿，不覆盖已有新稿。

outbox 登记正文、作品资料、目录、章节资料和定稿变更。D4 本地索引用独立消费者回执记录已追平的输入；原始事件保留，供后续摘要与模型消费者独立维护。事件记录本身不等于已经整理好的记忆。

## 本地数据布局

```text
作者选择的本地目录/
  studio.sqlite
  recovery/
    <checkpointId>.json
    <checkpointId>.saved.json
  books/
    <bookId>/
      book.sqlite
      backups/
        knowledge-v<原版本>-<UUID>/
          book.sqlite
      sources/
        <sourceId>.original
```

工作室数据库保存作品目录；每书数据库保存正文、知识条目、关系／事件／伏笔／人物认知、各自版本和修订事件，以及模型连接配置、固定发送上下文、候选与采用记录。目录标题与时间是缓存，书内元数据是依据。知识、故事与 AI 仓储借用作品连接，避免跨文件写入资产。当前只打开一部作品的连接；工作室连接持有独占锁，另一实例不能接管同一书库。实际锁行为、恢复和原生驱动兼容尚未运行验证。

数据库带 application ID 与 schema version。工作室库为 v2，新建与导入作品使用 book v10；已有 book v2–v9 保留对应功能，启用缺失能力须显式备份升级。v2 补知识结构，低于 v4 补故事结构，低于 v5 补记忆结构；v2–v5 再建立 AI 结构，v6 按原值复制运行与采用记录并替换结构，保留序号及历史上下文；v7–v9 保留 AI 表。低于 v8 才添加逐章任务结构，低于 v9 才添加分层汇总结构，最后追加向量结构；v9 升级只追加独立向量表及约束。未知数据库及早期 v1 格式拒绝写入，v1 迁移工具尚未实现。新建或导入失败会保留已创建资产；当前书库 `books/` 中结构有效的未登记作品可以扫描、预览并明确重新登记。未知、损坏或超限资产只报告跳过，不擅自修改。

正文支持段落、1–3 级标题、分场线、换行、加粗与斜体。段落身份使用 UUID；未知节点、重复身份、非法版本或跨作品章节请求拒绝保存。容量保护上限为每库 1,000 部作品、每书 1,000 卷和 20,000 章、单章 1,000,000 UTF-16 字符和 20,000 块；这些是输入边界，不是容量实测结论。

## 作者版本、目录与恢复

作品与章节资料、卷章重排和定稿使用作品修订号作条件检查；正文保存与历史恢复使用章节当前版本作条件检查。目录的全书章序固定为未分卷、卷顺序、卷内章顺序，建章与转卷后同步重排章号。归档作品可以阅读和导出，继续编辑需要明确解除归档。

历史列表每页最多 50 个摘要，按递增版本序号向前翻页；正文按选中的单个版本读取。恢复旧稿始终新建一个版本，记录恢复来源，保留恢复前正文。作者定稿记录独立指针；之后修改或恢复只推进工作稿，原定稿仍可阅读并按“仅定稿”范围导出。

正文保存冲突或服务故障时，主进程可独立将当前单章草稿、来源身份与纯文本另存为 JSON 文件。作者另存后明确选择重新读取，才会替换窗口草稿；若期间继续编辑，旧副本不能作为放弃新稿的依据。

本地服务仅在原进程已经退出时重建。恢复进程重开书库确定失败可重试；结果未知则继续核对原回执，不重复写入。关闭请求超时但迟到成功时，主进程先保留回执，再结束已关闭数据库的旧服务，等实际退出后允许恢复。数据库彻底损坏、运行中的服务长时间无响应以及 v1 格式迁移仍有后续恢复工作。

## 本书知识条目与来源

正文页的“本书知识库”打开当前作品的手工资料。打开前保存正文，面板期间锁定正文；知识表单单独维护未保存标记，关闭面板、换条目和关窗都检查该标记。创建与更新通过既有主进程白名单、输入校验和业务服务执行，写成功后同步作品修订号并刷新目录。

条目包括人物、地点、组织、物品、规则、主题和其他类型，以稳定 UUID 标识；名称、普通别名和说明支持字面检索，列表分页。知识性质、作者决定、新鲜度、冲突状态是独立字段。未来计划、人物认知与 AI 推断不会因“采纳”而自动变为世界事实。当前状态由作者标注；章节知识建议可经 AI 整理和作者审阅写入，人物认知记录及其修改历史仍在故事模块维护。故事记录自动维护、自动冲突判断、按时点推演认知和按章剧透控制尚未接入。

来源可以是作者输入、外部资料说明或本书正文引文。正文引用固定章 revision、段落 ID 和连续原文，写入前核对原稿；读取详情时按修订分组核对，每份修订只解析一次，不跨请求缓存全文。引用版本与当前章指针不同时标为“引用历史稿”；这不表示引文在当前稿已不存在。缺少段落或原引文时显示缺失／部分缺失，不跳到其他正文。外部资料只是手工出处记录，未自动核验实际外部内容。

知识变更在同一个 `book.sqlite` 写事务内检查知识修订号和归档状态，保存条目、追加来源、不可变修改快照、`knowledge_outbox`，并推进 `book_meta.revision` 与 `knowledge_revision`。正文 outbox 保持原结构，故事变更登记 `story_outbox`。D4 在整批索引发布时为三个队列记录本地索引消费者回执；有事件或本地索引回执，不代表模型记忆已完成维护。

知识条目与故事记录分别限制为每书最多 100,000 条，每条最多 200 个来源。知识别名最多 50 个，说明最多 20,000 字符，引文最多 2,000 字符。故事列表只返回标题、说明摘要、显式时间和伏笔阶段，详情再读取完整里程碑与状态变化。每页显示 50 条；故事详情返回最近 50 次修改的摘要，选中后读取单个历史快照，完整历史保留。输入上限与分页尚未经过百万字容量和响应耗时验证。

## 关系、事件、伏笔与人物认知

故事记录与知识条目共用 `book.sqlite` 的作品修订号和知识修订号。关系、事件、伏笔和人物认知使用联合字段；记录类型一经创建不可更换。关系两端、事件参与／提及、伏笔关联和认知主体都以同书稳定 ID 保存，事件锚点必须指向事件记录，认知主体必须是人物条目。被人物认知记录引用的人物不能直接改成其他知识类型。

故事时间只保存未知、日期标签或相对标签；只有作者明确填写的整数排序值参与列表排序，不能从自由文本日期或章节位置猜全序。读者披露位置另存为尚未披露、位置未知或固定章节 revision／段落；人物获知时间、获知事件和读者披露不互相推导。作者记录时间由不可变修订和来源创建时间记录。

伏笔按计划、埋设、推进、揭示、回收或放弃管理。已保存里程碑只追加，不允许修改、删除或调序；揭示与回收分开保存，未埋设的计划可追加带说明的放弃里程碑。回收与放弃为终局，揭示后仍可追加推进。状态变化以事件记录保留 before／after，不覆盖单一当前文本框。当前界面是作者全知视图，明确标注尚未提供读者或人物视角的防剧透过滤。

桌面接口提供 `story.list`、`story.get`、`story.revision`、`story.create`、`story.update` 五个命令。历史读取核对同书、记录、历史版本及类型；界面一次只保留一个选中快照。详情和历史快照附带关联名称，标签查询只读当前实体名称／事件标题；历史关联 ID 与内容来自不可变快照，显示名称采用当前值。关联选择器每次读取 20 个候选，搜索回车只触发该选择器的搜索。

知识写入超时或服务中断时保持表单挂载并锁写，在对话框内查询原回执。只有确认成功才清除未保存状态；确定失败保留编辑和原知识修订号，不能通过刷新列表直接换新基线覆盖并发修改。未知结果提供可复制的只读 JSON 草稿；作者确认留存后才转入恢复页，恢复不会自动导入副本或重新提交原写入。

## 旧作品启用知识库

状态查询只读取已有格式；知识状态的 `requiresUpgrade` 表示 book v2 缺少基础知识表，故事功能要求至少 v4，记忆状态要求至少 v5，原创作协作要求 v6，单章整理要求 v7，持久逐章模型任务要求 v8，分层汇总要求 v9，向量批次与混合检索要求 v10。已有版本可继续使用对应能力；启用缺失能力需勾选备份升级确认。升级成功回执带真实作品修订号与更新时间，界面先推进版本基线再刷新目录，刷新失败也不会退回旧的条件写入基线。业务服务对所有本地命令串行排队并等待完成，上限 8 个请求，切库与关闭不会插入备份的异步等待阶段；模型网络请求由桌面主进程异步执行，不占用本地服务队列等待网络。

升级为本书建立专属 UUID 备份目录，以 `wx` 创建空目标并记录文件身份，再等待 SQLite 在线备份完成。随后只读重开，核对 application ID、原版本（v2–v9）、书 ID、预期作品修订、`quick_check` 和外键，关闭验证连接后核验身份并执行 `fsync`。这些检查通过后，才在写事务内再次检查作品修订及归档状态。v2–v5 按原版本建立缺失的知识、故事和记忆结构，再建立 AI 结构；v6 专门复制原 AI 运行与正文采用记录、替换约束并建立知识采用审计；低于 v8 添加逐章任务结构，低于 v9 添加汇总结构，最后追加向量结构。旧 messages、提示版本或上下文指纹均保留，事务内检查外键后升至 v10 并记录作品变更。失败时保留目标文件，可能只有空文件或不完整副本，不自动拿它替换原库。

预建目标是依据 better-sqlite3 13.0.3 的备份实现：它会覆盖提供的目标，并可能清理失败时自行新建的目标。因此只传入本次独占创建且核验身份的文件，禁止传入任意已有备份。实现依据为官方 [backup.js](https://github.com/WiseLibs/better-sqlite3/blob/v13.0.3/lib/methods/backup.js)、[backup.cpp](https://github.com/WiseLibs/better-sqlite3/blob/v13.0.3/src/objects/backup.cpp)、[SQLite 备份语义](https://www.sqlite.org/c3ref/backup_finish.html) 和 [PRAGMA 检查说明](https://www.sqlite.org/pragma.html)。本轮仅静态核对并编写代码，没有实际运行备份或升级。

升级前副本只覆盖数据库，不包含 `sources/` 等全部作品文件，不替代 D6 完整恢复包。`quick_check` 不校验全部索引一致性，`fsync` 也不是已完成断电恢复实验的证据。只认识旧格式的应用无法读取 v10；未知版本和 v1 不会借此入口升级或重建。

## 持久整理与本地检索

“记忆与检索”面板打开前保存正文。六个有限命令为 `memory.status`、`memory.start`、`memory.step`、`memory.control`、`memory.search` 和 `memory.evidence`。任务、产物、发布指针与回执都在本书 `book.sqlite`；每次有界命令在现有服务队列中重新取得作品连接，没有持有连接跨异步等待的后台任务。

任务固定作品修订、知识修订和预期发布版本。规划每批最多读取 100 个来源的 ID、标题与固定修订，按来源类型和 ID 保存游标。索引每批处理一个来源，最多写入 64 个片段；按需读取单份章节或条目快照，不载入整本正文与历史。章节核对 JSON 摘要、纯文本和字数，知识／故事从不可变字段快照投影。正文保留块 ID；知识与故事使用带固定偏移的合成文本块。片段最多 1,200 UTF-16 码元，长块保留 200 码元重叠，避免边界断开常见查询词，同时避开有效代理对。

任务版本控制检查点条件写入；可暂停、恢复、取消和失败重试。失败批次先回滚片段与游标，再记录失败状态；相同版本的完整产物可复用。面板连续调度逐次等待确认回执并让出事件循环，停止或关闭后保留检查点。未知写入结果停止调度，沿用原请求回执核对和恢复入口，不能自动重放。任务重开后由作者继续处理。

暂存产物在发布前不可检索。最终 `IMMEDIATE` 事务重新核对作品、知识、发布版本、来源身份和完成计数，再登记新批次与 heads、条件推进 `index_publication_version`。输入变化的任务停止为 `superseded`。历史批次与产物保留，不用删除旧记录完成替换。最终发布需要批量登记该批次的全部 heads 和事件回执，工作量与来源／事件数量有关，尚未证明该阶段响应耗时。

`memory_event_receipts` 的消费者固定为 `local_keyword_entity_v1`，以消费者、队列名和事件 ID 去重，按统一作品修订号确认索引已追平输入。它不声称作品资料、目录、定稿等事件已完成模型语义维护；原始 outbox 的 `state` 不由此消费者改写。记忆面板的待索引变更按缺少此消费者回执计算，后续模型／摘要维护必须使用独立消费者进度。

检索只使用当前发布批次、完整产物和仍匹配当前原对象修订／标题的来源。关键词先转为安全 ASCII token：中文单字／相邻双字，其他文字按词；使用既有 SQLite FTS5 `unicode61`，用户输入不能成为 FTS 运算符。全文、名称／别名与显式实体关联分别读取最多 100 个候选，实体扩展最多 20 个，按排名融合并限制每个来源最多 3 个片段；返回最多 50 个片段，面板默认 30。候选截断有明确提示，不提供伪造的全库命中总量。这个索引消费者只整理本地来源摘录；章节模型整理和向量批次分别记录独立进度，向量检索边界见下文。

拒绝资料始终排除。作者的性质、采纳、新鲜度与冲突状态各自保留；未来计划不当作已经发生，人物参与或提及不推导知情。知识／故事的固定正文来源另登记为依赖；同一条目对同章取作者已引用的最高章节修订序号作为复核基线，追加当前稿引文后可推进基线，旧引文仍完整保留。来源编辑器在保存前说明这一规则；只修改采纳或重新整理不构成自动复核。章节当前修订不同于该基线时动态标记 `dependencyState=source_changed`，默认排除，作者可选择纳入并查看提示。历史引用仍可核对，变化标记不等同于认定知识错误，也不回写作者 `freshness`。覆盖状态分别显示版本匹配索引、引用原稿变化数和本地索引回执；整批 `current` 只表示输入版本覆盖，不表示全部陈述真实或模型理解达标。

出处查看重新核对发布 head、来源修订、内容 hash、块、偏移和原文切片；变化或丢失时明确报错，不跳到其他版本。知识／故事字段摘录与正文原稿分别标注，界面保持作者全知视图，未接入人物／读者防剧透过滤。原生 FTS 可用性、SQLite 查询与迁移、任务中断恢复、界面与长篇容量均未运行验证。

## AI 协作与候选采用

正文页的“AI 创作协作”打开前保存当前稿，面板期间锁定正文。作者为本书配置兼容 Chat Completions 流式接口的基础地址、模型名、上下文窗口与最大输出预算；每书最多 8 个连接。连接配置有独立版本条件，地址变化不能沿用旧地址的会话密钥。保存超时的待确认密钥仅暂存在主进程内存；原保存回执与当前连接都匹配后才启用，失败、失联或身份不符则丢弃，不重复提交配置。HTTPS 接口与本机 HTTP 可用，无默认厂商或自动备用接口。

先在本地保存发送预览，再明确发送。固定上下文包括作品、知识和章节修订、实际 messages、连接快照、来源、提示版本与 SHA-256 指纹。整章模式超限会拒绝；邻近模式在预览中明确范围，规划取章首、续写取章尾最多 6,000 UTF-16 码元／200 块，改写提供完整目标和前后各最多两个邻块。一次改写最多 200 个连续块且不能跨分场线。所选资料最多 12 片，发送前回查原文；未判断冲突的正文只作为叙述证据，知识／故事资料须由作者采纳且来源当前、冲突明确。人物认知、计划与推断保持各自性质。

来源与实际消息各受 80,000 UTF-16 码元上限约束。输入预算按 messages JSON 的 UTF-8 字节数乘 1.1 再加 1,024 估算，并预留最大输出；这是保守估算，不是精确 tokenizer 或费用承诺。全部实际 messages、出处、接口、预算、警告与指纹都可查看。作者资料模式使用当前章节、手选资料及至多 4 份作者手选的完整前文摘要；摘要通过独立任务审阅保存。读者资料模式另行核对附加故事资料的披露资格，边界见下文。自动检索规划、人物知情与完整防剧透上下文仍待后续。

全会话最多一个活动生成请求，主进程使用受控 POST、禁止重定向、180 秒超时、4 MiB 响应上限、128 KiB 流式行／事件上限和 60,000 UTF-16 输出上限。请求包含 `stream_options.include_usage` 与 `max_completion_tokens`；这些参数及不同兼容服务的流式行为尚未运行确认，官方文档获取也未得到可用结果。代码要求非空输出、`finish_reason=stop` 与 `[DONE]` 均满足才登记成功，其他结果保留部分输出及失败原因。

检查点在累计至少 1,024 个新字符且间隔至少一秒时保存；网络停顿时也检查这一条件，每次等待本地确认后才继续。未知内部写入立即停流，不重发网络或终态请求；界面查询原 `ai.claim`／`ai.checkpoint`／`ai.finish` 等真实回执，再读取当前候选。重开后没有活动网络的 running 记录可明确标记中断。配置与多步 AI 命令等待期间、活动网络期间，主进程都阻止切库、重启服务和关闭。关闭与恢复入口也检查未保存的 AI 要求、配置和作者改稿。

发送与采用都重核固定基线；作品、知识、原稿或来源变化时拒绝沿用旧候选覆盖新稿。规划追加至章节备注，续写追加章尾，改写仅替换选中的连续块；其他富文本块和独立定稿指针保留。原始输出与作者修改后的采用文本分别记录；正文／备注、采用记录、候选状态、作品修订及 outbox 在同一书内事务提交。嵌套正文保存不提前写跨库目录缓存，外层事务结束后再刷新目录。采用不自动建立知识事实或替作者定稿。

提议历史每页 30 条摘要，详情按需读取，分层汇总通过独立入口分页。采用回执先核对固定书章身份、任务、上下文、原输出、候选与作品版本；子面板确认接受后，父层才更新正文与目录基线。核对不符时保留编辑并锁写。未知回执保持面板与作者编辑，明确留存后才能转入恢复；密钥不进入可复制的恢复 JSON。没有自动重试、自动重发或自动续接已中断请求。未执行模型请求、数据库迁移、SQL、应用、类型检查、构建或界面验证；逐批向量和有界混合检索见下文，人物知情与完整视角过滤继续实施，长篇质量与容量仍在 D7。

## 完整单章整理与知识审阅

AI 面板新增“章节摘要”和“提取知识建议”，要求 book v7。仅固定完整本章已保存正文和作者整理要求，不把章节目标、备注或额外资料作为整理证据；完整章超过上下文或预算上限直接拒绝。整理使用独立提示版本 2，规划／续写／改稿保持版本 1，旧候选按原版本读取和校验。

原输出须是单个 JSON 对象。摘要恰好返回一条 `other`／`ai_derived`，抽取允许 0–20 条；每条说明最多 8,000 字符，携带 1–8 处本次固定段落的逐字引文，每处最多 2,000 字符。解析校验不修复或重写原模型输出；结构、知识性质或引文不符时保留原输出并禁止直接采用。符合结构也不代表语义正确，仍由作者审阅。

所有条目默认不选，冲突状态默认 `unchecked`。作者可修改名称、类型、别名、说明和冲突状态，原知识性质和引文固定，摘要类型固定。正文陈述、人物认知、AI 整理与 AI 推断保持各自性质，采用不会转成作者设定或客观事实。冲突未检查的知识继续受 AI 资料选择门禁限制。

采用前再次核对固定基线，按所选条目一次入库；每条的全部引文、条目历史、知识事件、作品与知识版本、固定采用审计和候选终态在同书外层事务提交，结束后再刷新跨库目录缓存。两个修订号各按所选条目数推进，候选版本推进一次。回执还核对所选序号、字段、条目 ID 与引文，通过父子面板确认后才清除未保存状态。采用不修改正文、章节备注或定稿。

未选条目只保留于原提议，同一候选采用后不能再采用剩余条目；暂不自动合并同名知识，也不自动写入关系、事件、伏笔或人物认知故事记录。采用历史从不可变审计读取固定字段与来源，后续编辑知识不会重写该快照。正文后续变化由 D4 依赖规则标记受影响，已有的本地索引仍需明确整理发布；本批没有登记模型摘要消费者已追平的回执。

恢复 JSON 包含逐条审阅草稿，不包含密钥。无效、未知或迟到回执保留编辑并暂停写入。迁移、结构化输出、引文核对、采用事务与回滚及界面均未运行验证；单章候选可独立使用，也可作为持久逐章任务的处理单元。已采用单章摘要的不可变审阅快照作为分层汇总的叶子来源。

## 持久逐章模型任务

“章节整理任务”按全书、单卷或未分卷章节建立 `summarize`／`extract` 队列，要求 book v8；未打开具体章节也可进入。五个有限命令为 `ai.task.status/get/start/step/control`。状态读取不建表、不推进任务；同书最多一个活动任务，保留最近十份任务入口和历史记录。

任务固定书名、范围标题及持久章序下的章节 ID、原稿修订、标题、卷归属和位置，最多读取 20,000 章元数据计算指纹，不在规划时载入全书正文。每步最多登记 100 章，详情每页 50 章，当前位置独立返回。原稿或范围变化使旧任务失效；采用知识导致作品与知识版本提升，本身不使剩余队列作废。每次准备候选使用当时最新两个版本，候选自己的发送与采用仍按固定基线校验。

每章依次经过本地预览、明确发送、作者采用或拒绝，再明确登记作者决定。任务不会自动发送下一章；prepared／running／succeeded 候选重入时复用。准备候选、绑定单元和新增不可变尝试在同一外层事务内；采用知识沿用独立采用事务，之后由下一次 step 登记审阅进度。每个成功 step／control 条件推进任务版本一次，原请求未知时只核对回执，不重放写入。

失败、取消、中断或候选基线过期先登记失败检查点，明确重试后可另建候选，原尝试和输出保留，再次发送仍需确认。暂停只控制队列，不会终止已经发出的网络请求；当前章 running 时必须先取消生成或核对后标记中断，才能跳过或取消队列。新候选使用固定连接 ID 的当前配置，便于调整预算后重试；任务记录的连接名与模型是创建时展示值，实际发送以各候选固定预览为准。

独立消费者 `chapter_model_review_v1` 按类型、章节、原稿修订和标题去重，记录作者采用／拒绝过的历史来源。跳过不计入来源审阅数；计数可能包含旧稿，不表示当前全书覆盖、知识全部采用或模型理解达标。它不改原 outbox 状态，也不写 D4 `local_keyword_entity_v1` 的事件回执。

面板区分活动任务和历史记录，保留未采用的审阅修改、未知请求编号和恢复 JSON；密钥不进入恢复资料。历史任务不再发送或采用；失效或归档任务中没有活动网络的孤立 running 候选，仍可在主进程核对后明确标记中断，保留输出并解除关闭锁。任务持久化、分页、重试、事务回滚、重开恢复与界面尚未运行验证。逐章整理、分层汇总和向量批次分别记录进度，自动模型事件维护仍待后续。

## 卷与全书分层汇总

“分层汇总”要求 book v9，可选全书、一个卷或未分卷范围，每书最多一个活动汇总任务。七个命令为 `ai.summary.status/get/node/start/step/control/adopt`。开始时要求范围内每章都有与当前原稿修订和标题一致的已采用单章摘要；缺少时拒绝创建并报告缺少数量。每章按运行序号选择最新的符合条件摘要，实际文本取不可变知识采用审计，不取知识条目后来编辑后的字段。

任务固定书名、范围标题、持久章序、章节身份、原稿修订、卷归属与位置，以及选中的摘要运行 ID，只读取元数据清单。每组可选 2／4／8 份完整下层摘要，默认 4；按章序自底向上规划，单章也有根节点。最多 20,000 章、40,000 个节点；每步最多规划 100 个节点，详情每页 50 个。第一层读取已采用单章摘要，更高层只读取作者已经批准的直接子节点，不绕过未审阅依赖。

一次只在本地准备一个节点，作者核对实际 messages、来源与预算后明确发送；审阅并采用后，仍须明确准备下一个。复用 `summarize` 候选与既有流式网络，独立提示版本为 3，通过 `context.summary` 区分；旧创作版本 1 和单章整理版本 2 的指纹规则保留。首来源章仅是既有运行表的存储锚点，正文块、选段、原文和额外检索证据为空，不能据此声称已把全书正文发给模型。

每份来源与作者采用的节点摘要最多 8,000 字符。完整来源及消息受 80,000 字符与估算窗口门禁约束，估算仍为消息 JSON 的 UTF-8 字节数乘 1.1 向上取整再加 1,024，并预留最大输出；超限拒绝，不能静默截断。输出严格为单个 `summary/citations` JSON；每个直接来源至少一处逐字引文，共 1–16 处。界面区分“下层摘要引文”和叶子附带的“原稿引文”，汇总始终是 `ai_derived`，不把作者采用变为客观事实。

采用同时保存不可变节点文本、候选采用状态、任务批准计数、作品版本和 `book.metadata` outbox，外层事务结束后再刷新目录缓存。候选和任务版本各推进一次，作品版本推进一次，知识版本不变；不自动建立知识条目。父子面板核对任务状态与计数、节点、候选版本、原输出、固定上下文和两个基线后才清脏及推进父层版本。普通单章列表、知识采用与逐章任务入口排除汇总候选。

来源新鲜度比较完整清单指纹，不比较任务开始时的作品版本，避免节点采用自身使后续任务失效；准备、发送和采用仍核对候选当前的作品与知识基线。改稿、标题、范围顺序或新的已采用单章摘要会使旧汇总来源失效，历史文本仍保留。已有 prepared／running／succeeded 重入复用；失败、拒绝、取消、中断或候选基线过期先登记失败，再明确重试，尝试记录保留，不提供跳过。暂停不终止网络，running 时不能重试或取消任务；历史／归档的孤立 running 仍可明确核对中断。

汇总面板保留作者编辑、未知回执和不含密钥的恢复 JSON。新候选采用固定连接 ID 的当前配置，任务名与模型展示值保留创建时快照。分层汇总尚未自动进入创作召回或 D4 索引；数据库约束、真实生成、逐层覆盖质量、百万字容量、恢复和界面均未运行验证，统一验收仍在 D7。

## 创作中的前文摘要

book v9 的创作面板可明确读取已采用的分层摘要，通过 `ai.context.summaries` 按页选择；本批沿用 v9，不新增迁移。候选按任务创建时间与 ID 倒序、节点层级倒序和序号正序读取，每页最多核对 20 个节点，以最后检查节点作为游标。来源过期或覆盖当前章及后文的节点不显示，空页有后续游标时仍可继续。翻页只保留当前页，作者选择独立保留，最多 4 份。旧 v6–v8 的普通协作保留，可在应用内明确备份升级后使用摘要选择。

准备预览时仅接受任务、节点、采用候选 ID 和不可变清单指纹，服务回读已批准节点、采用文本与候选上下文的身份及完整性。来源有效性按节点实际覆盖的全部章节比较原稿修订、标题、顺序、卷归属／标题／位置及最新已采用单章摘要 ID，同时核对书名和范围标题。追加后文或覆盖范围外的内容变化不使完整前文摘要失效；范围内插章、换序、改稿或重新采用章节摘要会拒绝使用。原任务失效或取消不会删除已经批准的资产，来源仍匹配的节点可以继续手选。

节点首末章必须完整位于目标章之前，跨越目标章的摘要直接拒绝。多个摘要的首末章范围和实际覆盖章节均不得重叠。每份仍最多 8,000 字符，整份加入，超预算拒绝。固定快照保存任务、节点、采用候选、清单指纹、覆盖指纹、首末章修订与标题、采用时间和全文；实际来源可沿任务清单和节点审计追溯，不把完整全书清单重复放入消息。

只有带摘要的规划／续写／改稿使用提示版本 4；未选摘要保持版本 1 的 messages 与指纹字段规则，完整单章整理保持版本 2，汇总任务保持版本 3。单章整理和汇总生成都不允许附加创作摘要。发送与采用沿普通创作链路重新读取来源、组装全部 messages 并核对指纹，保留作品、知识和目标章版本门禁。

面板展示摘要全文、覆盖范围、采用身份与指纹；只有核对本次输入、连接、选择和摘要全文快照的正常或迟到预览回执后才清除创作编辑状态。未知结果锁写并保留摘要选择，恢复 JSON 包含创作表单和已选摘要，不含密钥。选择摘要后仍需明确保存预览、明确发送和作者采用。

前文章序限制仅作用于所选摘要，不过滤其他资料、目标备注或作者指令；它不等于人物知情或读者披露过滤。提示保留 `ai_derived`、压缩遗漏和推断的不确定性，不把作者采用当作事实认证。源码已接线，实际数据库读取、分页、来源变化、历史兼容、真实模型与界面行为均待获准运行验证；长篇质量、容量与性能仍在 D7。

## 附加故事资料的读者披露资格

创作准备可选择作者资料或读者已披露资料，缺省沿用作者资料。读者模式仅限制手选的附加片段：它们必须是作者已采用、来源当前、冲突已核清或解释的故事记录，且作者标注的披露章节、修订和段落仍可在当前原稿核对，披露章严格早于目标章。当前章内的先后位置不作推断，未知、未披露、历史修订或后文披露都阻止准备。

披露元数据从同一固定故事修订重新读取，不写入索引正文，也不改变既有投影内容指纹；无需 schema 升级。正文和知识条目缺少独立披露资格，完整前文摘要也没有逐项披露许可，因此读者模式拒绝使用。伏笔投影混合计划回收与全部里程碑，资格保持未知，避免把首次披露当成整份投影的许可。

读者模式使用提示版本 5，把资料范围与固定披露锚点纳入实际消息、预算及上下文指纹；准备、历史回读、发送和采用均保持资格及版本边界。作者模式省略新增范围字段和披露元数据，保留原有提示版本 1／2／3／4 的消息结构。界面切换范围标为未保存，预览回执核对相同范围后才清脏；恢复内容保留范围与选择。

此资格依赖作者对故事记录的披露标注，不自动判断整段陈述的真实披露程度。当前章正文、作者要求、章节目标和备注仍按预览发送；人物知情、故事时间和读者披露继续独立处理。检索界面仍是作者全知视图，本批只在创作预览中限制附加资料。数据库、历史兼容、模型与界面行为均未运行验证。

## 向量批次与混合检索

book v10 在本地已发布片段之上追加独立向量配置、请求和缓存。作者选择本书已有模型连接并明确填写向量模型，先准备本地预览，再明确发送；会话密钥沿用主进程内存中的连接配置。索引请求最多包含 8 个完整有效片段，按保守预算缩小本批数量；纯空白或含空字符的片段排除向量整理及覆盖统计，原文不改写。查询请求只发送检索文字，准备、领取与成功保存时均核对筛选内仍有同配置的可用向量和实体身份。完整输入、连接基础地址、向量模型、发布版本、来源身份、输入估计和指纹均随预览保存。准备及读取历史不发起模型请求，后续批次仍需再次明确准备与发送。

配置指纹绑定完整连接快照与向量模型；连接版本、地址或模型变化后使用独立缓存。首个成功批次固定实际响应模型和维度，后续整理与查询必须一致。主进程请求 `embeddings` 的浮点数组格式，校验条数、唯一序号、有限数值、非零向量及最多 4,096 维；归一化采用缩放计算以避免溢出。请求限时 120 秒，响应限额 2 MiB，不重试或重发，接口兼容性仍需真实请求验证。

准备和发送核对当前发布指针、当前连接与固定出处，写入向量前再次回读。成功缓存和请求终态在同书事务内保存；来源变化或结果不符会回滚整批并保存失败状态。向量批次不推进正文、知识修订或本地发布指针，不改原始 outbox 状态和关键词消费者回执。请求与旧缓存保留，文本散列用于核对缓存来源，语义向量来自作者明确发送后返回的模型数组。

混合检索按相同来源、性质、实体、审阅及依赖状态筛选，按片段编号最多逐个比较 5,000 个已有向量，取前 100 个语义候选与关键词、名称和实体候选进行排名融合；每个来源仍最多 3 个结果。返回覆盖片段数、已有向量数、实际比较数与扫描上限，覆盖不足、扫描不足和候选截断明确标记。结果属于本次固定批次的查询快照，出处入口仍须回读有效原稿；检索界面为作者全知视图。当前上限不代表大书的完整语义召回，自动创作检索规划、人物知情过滤和容量／效果评测继续在后续阶段实施。

每个请求从 prepared 版本 0 开始，claim 后为 running 版本 1，成功、失败或中断后为版本 2；准备阶段取消为版本 1。主进程活动与待确认写入同时保护切库、配置和关闭，读取回执只核对原请求。界面支持取消活动网络或明确中断没有活动网络的历史请求；查询原回执会核对本次操作可能执行的内部步骤，读取失败暂停轮询且不重发写入。未确认请求阻止切换，进入恢复前须明确确认已复制配置、查询和原请求编号；恢复内容不包含密钥。SQL、迁移、网络、重开恢复和真实界面均尚未运行验证。

## 章内查找与专注写作

查找限定当前章，支持大小写、上下一处、当前替换和全部替换；Ctrl+F／Ctrl+H 打开，Esc 关闭。匹配可跨同段落的粗斜体片段，不跨段落或硬换行。文字按字面处理；替换保留段落身份，使用匹配起点的字形格式，一次全部替换构成一个可撤销事务。为控制长章开销，超过 2,000 处只显示前 2,000 处并禁用全部替换。归档作品允许查找、禁止替换。

## 草稿检查点与回导

未保存正文在停笔 800 ms 或持续输入 5 s 后尝试写检查点；输入法组合期间等待文字落下。检查点由主进程写入当前已确认书库的 `recovery/`，带书库 scope、编辑会话 UUID、编辑序号、原章及基准 revision。切书库后旧 scope 拒绝写入；每次重新加载正文产生新的会话，迟到回执不能更新新稿的留存提示。

检查点使用独占新文件和同步落盘。只有成功回执覆盖到的同书库、同书同章且正文 hash 一致的既有检查点才登记独立 `.saved.json`；保存未知或标记失败保留候选。保存成功后才到达的检查点仍可能出现在列表，作者需核对正文后决定是否恢复。列表保留每次编辑会话最后一份有效候选，不删除此前文件。

应用意外退出后，重新选择相同书库，进入目标作品的“从草稿恢复新章”预览检查点，也可以原生选择另存的 JSON。主进程严格校验 UTF-8、格式版本、身份、时间、正文结构和纯文本一致性；预览 token 固定原字节和目标作品 revision，有效 30 分钟，确认前消费。界面确认后在目标作品建立新章；新章和段落使用新 ID，来源原字节保存到 `sources/`，备注记录原书、原章、基准版本与时间。来源登记、新章、正文 revision、作品 revision 与 outbox 在同一书内事务提交。原章和历史保留。

单章副本与检查点限制为 16 MiB；恢复目录限制为 10,000 项／512 MiB，达到后暂停新增并提示。已有副本、标记和部分写入文件均保留，损坏文件只报告跳过。检查点用于恢复最后已落盘的内容，不能保证保住落盘前的输入，也不替代完整作品备份。目录扫描耗时、真实崩溃与断电恢复需运行验证。

## 文本导入与导出

导入只读取作者在原生对话框选择的 TXT／Markdown 文件；编码选项为 UTF-8、UTF-16LE、UTF-16BE 和 GB18030。不能严格解码时拒绝导入；实际可用编码取决于打包运行时，当前尚未执行验证。预览会提示编码标记与换行规范化。自动分章保留原始标题行、卷首文字和空白；Markdown 当前按字面文字导入，并在预览中说明。

预览 token 绑定书库与解析结果，最多保留一个会话、有效期 30 分钟；调整编码或分章会生成新 token。每次确认先消费 token，再保存全新的作品及原始文件副本，避免重复确认重复建书。输入保护为 32 MiB 原始文件、800 万 UTF-16 字符和 20 万段落；单章与章节数继续遵守正文上限。超限时保留源文件并说明调整方式，不截断正文。

导出固定当前作品修订号，在一个读事务内逐章读取当前工作稿或各章最近定稿。UTF-8 TXT／Markdown 导出始终保留章间空行；作者选择是否额外加入章节标题，已含标题的导入稿可能需要关闭此项。Markdown 保留支持的基本排版，但文本交换不承诺与原始文件逐字节相同，也不携带完整历史和知识资料。

导出及草稿副本采用 `wx` 创建新文件并同步写出；同名文件不覆盖，失败产生的空文件或部分文件保留并说明路径。文件路径只由原生对话框产生，界面不能调用任意路径读写。
