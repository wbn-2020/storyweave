## 数据与入口

继续使用工作区目录库和每书独立的 SQLite。M2 交付格式为 book v16，工作区保持 studio v3；v15 及更早作品经已有的“备份并升级”流程追加结构。读取旧书只返回升级提示，不隐式修改库。v14／v15 恢复包继续使用各自的结构基线；v16 恢复增加演进资料校验。后续 M3 的当前新建格式为 book v17，追加内容见[角色工坊与历史状态](角色工坊与历史状态-2026-11-10.md)。

| --- | --- |
| `living_outlines` | 总纲、卷纲、章纲的当前修订指针；节点 ID 分别沿用作品、分卷、章节 ID |

## 大纲修订与作者保护

总纲、卷纲和章纲使用同一组字段：标题、纲要、目标、冲突、收束或悬念、可空紧张度及最多六个节拍。旧章节、卷和开书总纲先作为可读基线；首次保存或明确准备演进预览时建立修订记录。

每次内容保存都追加新修订。章纲的标题、目标、冲突、悬念、紧张度和节拍同步到章节计划字段；卷纲同步到分卷目标。其他入口改动这些字段时，已保存的大纲会提示待复核。模型不能替换锁定章纲；作者需要明确解锁后编辑。只切换锁定时复制旧依赖，不覆盖其他入口的计划改动，也不表示已经完成复核。

恢复历史会创建新修订，并复制所选历史的依赖。因此旧版本恢复后仍可能待复核。作者核对内容后可以编辑保存，或明确选择“确认内容仍适用，保存复核修订”；该修订表达作者当前判断。已有历史及旧派生依赖保留。

修纲仅处理同一卷内最多十个尚未写作的计划章：状态为 `planned`、正文计数为零、未有定稿、未锁定。替换作者已有章纲须逐章确认。界面对照使用预览时固定的原章纲；待采用的所有字段和节拍可编辑，采纳时再次核对目标修订及作者确认范围。

滚动补纲每次追加一至三章，沿用现有末章所在卷。固定全书／卷方向、末尾相邻章纲及其有效记忆；已有计划章节仍占据顺序，不跳过最后一个已建章。当前不提供跨卷批量修纲或自动创建后续分卷。

## 记忆发布与来源

整理对象必须是当前工作稿对应的作者定稿。预览只固定完整参考章正文和本次明确选入的实体；不把章节目标、备注、后续计划或其他章记忆作为本章事实依据。输出包含摘要，以及可逐项取消的事件和人物状态。

每项保留一至八处固定段落 ID 和逐字引文，采纳时核对引文确实位于该段。事件和状态区分正文陈述、人物信念与模型推断；摘要始终是整理资料。作者可改说明和性质，不能把引文改成另一份来源。状态只能引用本次明确选入的人物身份，不据此推断其他人物知情。

发布使用一个事务创建新批次、替代旧发布指针、保留旧批次并登记采用回执。批次内容和定稿修订不可变；当前发布不等于当前有效，依赖过时仍显示待复核。尚未生成或尚未采用的内容不会发布。

## 依赖身份与失效传播

大纲依赖的目标 `target_id` 是**派生大纲修订 ID**，大纲来源 `source_id` 是**节点 ID**，`source_revision` 是当时的来源修订 ID。记忆目标及来源均使用不可变批次 ID。这个区分使每次历史修订可以保留自己的依赖，恢复旧纲不会丢失来源。

正文来源令牌使用规范 JSON 数组，依次记录工作稿修订、定稿修订、章节位置、卷 ID、标题和章节状态。恢复时严格解析结构并核对工作稿与定稿历史，标题中的斜杠不会影响拆分。实体核对已采用、当前且无候选冲突的最新知识修订；预览准备、正式采用的来源复核与后续依赖失效使用相同规则，出现候选冲突时相关派生内容转为待复核。创作约定核对其修订号；历史固定预览保留原文，不按新状态重写。

读取快照时比较当前来源版本，再沿依赖图传播待复核状态。大纲上游传播使用所依赖的具体来源修订；每个失效目标只入队一次。锁定不抑制失效提示，失效不自动改正文、重写大纲或请求模型。

作者视角的规划、续写与改写可明确携带本书／本卷／本章的有效大纲，以及**最近三个前文章节范围内**有效且已发布的记忆。不拿更早批次补足三个名额，不发送未来章记忆，不把无效资料继续当作有效上下文。读者、人物视角、审稿、拆书及章节知识整理不使用这一选项。

## 采纳事务与恢复核对

模型请求在作品写事务之外进行。正式采纳使用立即事务，核对作品版本、知识版本、模型任务版本、来源及目标，再写入正式数据和回执。一次采纳只推进一次作品版本。

补纲的空白正文修订、新章节、章纲历史、各章 `chapter.changed` 事件、作品结构事件和采用回执共用该事务。采纳结束后才读取作品快照、刷新可修复书架目录。重复采用相同内容返回原结果身份；不同内容返回冲突，不重复建章。

v16 单书恢复在现有数据库身份、结构、外键和基础业务检查之上，追加固定原稿比对、章纲／实体历史比对、记忆批次比对、采用终态与回执内容比对、目标身份及依赖来源存在性检查。固定预览中的历史批次可以已被后续批次替代，不因此篡改历史预览。

演进面板在读取、模型控制或写入结果异常时提供完整内容留存：当前大纲和原基线、请求表单、提案及已读模型输出、最近一次操作尝试参数、原写入及读取错误编号。历史恢复记录保留所选修订，模型控制记录保留动作与固定任务身份。作者手动复制并确认当前完整记录后，可从面板直接进入草稿与服务恢复；记录变化会使旧确认失效。这份手动留存不包含尚未读到的模型尾部，主进程终态补存仍沿用原流程。

读取失败的原请求编号不会被后续无编号错误抹掉；有新编号时记录新的失败请求。核对原读取只查询请求状态，待处理、未知或不确定错误仍保留编号；确定结束后不把迟到结果填回表单，也不重发模型操作，作者再明确刷新或读取原提案。写入仍使用原采用／保存回执核对。

## 界面与有界读取

作品导航提供写作台、大纲与演进、角色与世界、记忆星图入口；定稿记忆可从定稿提示和作品菜单进入。五域状态显示资料是否存在、是否有待处理提案或待复核，不限制作者进入顺序。写作左栏显示目标、冲突、悬念和节拍，节拍扩写复用原有正文候选与差异采纳链路。

“进入本章写作”和“打开来源章节”复用完整开章流程，先经过正文与表单保护、核对作品及章节身份，再切回正文画布。目标已经是当前章且版本未变时保留编辑器实例和撤销历史。来源章节入口打开当前工作稿，历史定稿修订与引文仍显示在记忆记录中。

保存或采用带回的新创作快照会撤销此前后台读取的回包资格；迟到的旧快照及错误不能覆盖已确认的新快照。该保护在当前窗口的请求序列内生效，跨窗口仍通过作品版本及来源修订核对。

大纲历史每页三十条；快照只显示最近五十个记忆批次、前二百个可选实体和最近三十次提案，并显示总量。可选实体及其总量、角色／世界状态只统计已采用、当前且无候选冲突的实体。当前大纲及章节计划各有 4 MiB 读取预算，快照为 8 MiB，依赖边最多读取十万条；超过预算明确报错，不静默截断后继续生成。模型来源和输出另受现有上下文预算与严格 JSON 解析约束。

这批实现提供最小记忆发布及演进流程。自动语义偏航诊断、完整历史人物心智、角色试戏、世界锻造、出场矩阵和伏笔雷达继续按 M3–M5 推进；记忆发布也不等于已进入旧知识索引或自动更新人物认知。
