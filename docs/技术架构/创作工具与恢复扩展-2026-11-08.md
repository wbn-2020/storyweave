# 创作工具与恢复扩展

编写及更新日期：2026-11-08。本文补充[原实现基线](技术架构与实现基线-2026-11-06.md)，描述当前源码的数据与接口边界。功能入口见[补齐说明](../产品文档/创作工作台补齐说明-2026-11-08.md)及[创作流程完善](../产品文档/创作流程与参考工具完善-2026-11-08.md)，实际检查与未运行事项见[开发进度](../开发进度/开发进度-2026-11-06.md)。本文不构成运行验收。

## 数据归属与版本

工作室目录库仍为 `studio.sqlite` v2；新建、导入作品使用 `book.sqlite` v14。已有 v2–v13 仍按原能力读取；新工具读取返回 `requiresUpgrade`，不隐式升级。启用新结构时复用备份升级入口，在独立目录留存原数据库并校验，事务内再次核对作品版本后追加结构。v12→v13 追加创作工具结构；v13→v14 追加人物档案列及日历、预设、图片结构，更旧版本依次保留原有迁移分支。v1 与未知格式仍拒绝写入。

| 数据 | 位置与范围 | 不可混用的含义 |
| --- | --- | --- |
| 创作约定、场景、审稿、目标、写作记录 | 每书 `book.sqlite` | 场景计划不等同于已发生事件；审稿建议不等同于作者认定的事实 |
| 全局灵感与拆书记录 | 书库根 `inspiration.sqlite` v1，application ID `0x53545749` | 独立于某部作品；首次保存才建库，空列表读取不创建文件 |
| 返回写作位置 | 按规范化书库路径隔离的界面偏好；失败时用会话内存 | 不属于正文或备份，不作为放弃草稿的依据 |
| 自动草稿 | `recovery/` 与其 `generations/<id>/` | 保留历史代，不搬移或清空旧文件 |
| 待提交模型终态 | `pending-model-results/` 旧根日志与 `volumes/<id>/` 新卷 | 只用于补存本地结果，不重发模型请求，不保存连接密钥 |

v13 包含 `workbench_settings`、`scene_cards`、`review_issues`、`writing_goals`、`workbench_revisions`、`writing_activity`。后两者以触发器禁止更新与删除。全局库以 `inspirations` 保存当前记录，`inspiration_revisions` 保存不可变历史；目录库版本没有因此升级。

v14 在 `knowledge_items` 追加可空的 `character_profile_json`，档案随已有知识修订保存历史；新增 `calendar_entries`／`calendar_entry_history`、`ai_presets`／`ai_preset_history`、`book_media`。日历和预设历史禁止覆盖；图片只追加新记录，以最新记录选择当前封面或人物立绘，原图和元信息均保留。新建、显式升级和恢复结构白名单采用同一版本边界；恢复清单契约接受 v14。

## 保存与引用

创作工具写入同时检查作品修订和条目修订，拒绝归档作品与旧基线。当前值、不可变历史和作品修订推进在同书事务内完成。提交后同步书架缓存与界面目录；请求超时保留表单并查询原请求，确认写入但目录同步失败时保留重试入口。

场景可无章节、无正文先存在；人物与地点引用稳定知识 ID。绑定正文时保存章 ID、固定修订 ID 和块 ID。人物／地点被当前场景引用时禁止直接改变条目类型，归档场景也参与检查；历史场景仅要求所引身份仍存在。场景排序不重排正文。

审稿问题的原始定位、证据与理由取自首次不可变历史，当前定位可用于后续复核。正文修订推进后显示依据过期；标记解决要求有效的当前定位。应用修改必须明确选择连续段落，核对作品、问题和正文版本，正文新修订与问题的“待复核”状态同事务保存，旧原稿和判断保留。

`revision.merge` 在当前稿与固定来源之间选择段落差异，保存新的 `restored` 修订并在插入时记录恢复来源，不更新旧历史。AI 文本差异组件只生成作者选择后的待采用文本，最终保存仍经过原有采用事务与版本门禁。

## AI 与人物认知

作者视角的固定上下文包含作品题材、简介、故事前提、叙述与风格约定；读者／人物受限上下文不自动携带这些可能泄露未来的信息。历史候选保留原上下文与提示版本，新旧提示重建走对应分支。

审稿使用已有 `plan` 存储类型加 `purpose: 'review'`，不改旧表的任务类型约束；审稿候选不能走普通规划采用入口。知识抽取支持创建、关联并追加出处、明确修订、忽略，已有目标由稳定 ID 与预期修订核对，同名不自动合并。

`creativeResources` 保存作者选定场景、笔记、全局资料和内置方法的固定 ID、版本、内容及使用要求。来源进入发送消息、预算和上下文指纹，发送／采用前重建核对。旧候选未附加资源时保留旧结构。人物档案的“省略保留、空对象清空”由字段合并规则统一处理，AI 采用审计记录实际保存的完整字段。

拆书使用 `kind: 'plan', purpose: 'study'`，仅接受选定的全局参考资料。正文、章节目标、创作约定、本书记忆和前文摘要不进入该任务。输出严格解析为最多 30 项，逐字引文只匹配资料正文；出处信息不混入原文。`study.adopt` 核对候选版本和来源版本后，在全局库事务内写入作者选定条目及不可变历史，保留来源 ID、版本、引文和候选身份。相同客户端 ID 只确认完整一致的保存；同一候选条目重新打开后不会凭新 ID 重复建立记录。

任务预设属于本书，每任务只允许一个未归档首选项；替换首选项和各条历史在一个事务中完成。应用预设只填入 composer，不调用模型。用量读取已有 `ai_runs.usage_json`，未发送预览不计入运行，缺失或无效 token 字段保留为未知，不推算费用。

认知变化追加形成／修正／推翻／隐瞒／遗忘状态，保存前态、有效截止与知识来源。已保存主体、内容和故事时点不以编辑覆盖；查询按作者明确排序值选取有效状态。旧认知编辑历史未记录明确故事时点，不能反向推定。人物视角仍需通过真实样例验证间接剧透边界。

## 写作记录与全局收集

正文修订提交时同事务登记 `manual`、`ai`、`import` 或 `restore` 来源。新增、删除按保存前后文本估算，净增按非空白 Unicode 码点差计算，含标点；时段由作者手工登记。普通编辑、AI 采用、导入和恢复的内部来源参数分别接线，renderer 不能任意伪造保存来源。默认汇总最近一年，不声称统计敲键次数或自动计时。

全局灵感支持父子关联、出处、标签、作品关联与归档，父子链检查防环及深度上限。复制到作品笔记使用固定目标 note ID，重试先核对该 ID 的完整内容；超出笔记内容上限明确拒绝，不截断原文。原灵感及历史仍留在全局库。

参考文件导入限制为 UTF-8 TXT／Markdown、每次 1 MiB。原文按最多 30,000 字符切段并保留空白，父条目与全部分段同批保存，固定客户端 ID 用于完整内容幂等核对。日历计划独立于实际写作统计，勾选完成不会登记产出。

图片仅接受 PNG／JPEG／WebP，契约检查规范 Base64、签名与边界，仓储核对字节数、SHA-256、人物归属及容量。单张原图 2 MiB，每书 100 张、合计 64 MiB；列表只返回元信息，按需读取单张原图。图片没有远程下载或生成入口，随本书数据库进入恢复包。

## 导出与恢复

导出分为 `prepare`、固定章节预览、原生选路径、`commit`。预览 token 固定作品修订、所选章节及修订、排除原因、格式与 manifest hash，提交不自动套用新版本。成品为 TXT／Markdown／EPUB／DOCX，另存清单；使用独占创建与同步写入，不覆盖已有目标。取消路径选择不提交；部分失败保留已创建文件并说明，不能把只生成一个文件视为全部成功。DOCX 复用 ZIP 写出能力，按章写入 WordprocessingML，前言、后记与排版选项进入固定清单；不嵌入素材图片。

恢复包预览除文件 hash、schema 与外键外，还检查领域字段、来源身份、v13 工作台及 v14 档案、日历、预设与图片数据。旧 v13 按旧结构白名单校验；当前格式按完整新结构校验。未完成目录只有在包身份与已有内容均能核对时续办；不匹配或部分文件无法确认则保留原目录，改用其他书库恢复。单书包包含该书数据库与已登记导入原件，不包含全局灵感、书库目录库、自动草稿、待提交模型结果或升级备份。

草稿当前代限制文件数与字节数，到 80% 提醒，达到上限停止追加并提供建代入口。新代以不可变代记录发布，旧代仍可预览；成功建代立即重试当前未保存稿的保护。

文本和向量请求在 claim 前先检查目录可写性与至少 5 MiB 的可用空间，并留存不含正文或密钥的预检记录。每卷按 10,000 项／512 MiB 的 80% 阈值提前承接到新卷，不删除、搬移或覆盖旧日志；旧根日志仍可读取。分卷身份与预检记录不可变，完整终态再写入该卷，之后才向业务进程提交。

重开书库按原候选与固定上下文核对并补存，完成后在原卷追加独立标记，残件继续保留。满卷仍能读取并追加小型完成标记。预检不能锁定未来磁盘余量，生成途中不足 1,024 字符的未保存尾部仍可能随异常退出丢失；这不同于已经完整落盘的终态。结果身份冲突、日志损坏或磁盘空间不足必须显示可处理状态；仍需异常中断的运行验收。

## 检查边界

本轮实际采用源码阅读、调用链对照、独立静态复核和只读文本检查。未启动应用、运行测试、类型检查、编译、构建、打包、安装依赖、请求模型或操作真实作品库。未新增或改写单元测试。数据迁移、关闭与恢复故障、输入法、真实导出及阅读器兼容不在本轮已运行结论内。
