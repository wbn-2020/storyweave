# 织章：产品设计基线

日期：2026-11-03。状态：供用户审阅的产品与交互方案，尚未实现正式应用。

## 1. 产品决定

**工作名：织章 · StoryWeave。**“织”对应情节之间的关联，“章”对应最终可编辑的正文。

核心用户是希望用 AI 辅助构思和写长篇故事的个人创作者，也包括没有写作经验但愿意逐章审阅的新手。第一版不依赖本地大模型或 GPU，通过服务端连接用户授权的模型 API。

**一句话价值：在同一个创作空间里看清故事结构、写出章节，并知道一次修改会影响什么。**

最终交付给用户的是作品和创作资产，不是大量聊天记录。画布与编辑器分别服务结构思考和细读修改，二者应能相互定位。

## 2. 主旅程

```text
建立作品意图
→ 整理卷／章目标与情节关联
→ 为一个章节选取已确认设定和相关情节
→ 得到可编辑的草稿建议
→ 审阅正文和设定影响
→ 确认局部修改并生成新版本
→ 导出或继续下一章
```

用户可以从已有正文开始，也可以从一张人物卡开始。系统不强制先填完世界观、全文大纲和所有人物表单才允许写作。

## 3. 模块与入口

| 主模块 | 用户完成的任务 | 输入 | 输出 | 连接到哪里 |
|---|---|---|---|---|
| 作品概览 | 确认创作意图、找到当前作品和下一步 | 题材、故事种子、作品状态 | 作品工作区、下一步动作 | 大纲、画布、编辑器 |
| 卷章大纲 | 安排卷和章节的目标、冲突、章末转折 | 作者意图、已有情节 | 可调整的章节目标 | 画布和生成上下文 |
| 故事画布 | 把情节、动机、线索和伏笔关联起来 | 情节节点、依赖、章节归属 | 可读的结构图与选中对象 | 对应正文、设定和审阅 |
| 章节写作 | 编辑正文，比较和接受局部建议 | 当前正文、选区、版本化上下文 | 用户确认的章节版本 | 设定建议、审阅和导出 |
| 人物与世界 | 维护人物、世界规则、时间线和伏笔 | 作者设定、提取建议、出处 | 已确认事实、待确认建议 | 画布与上下文构建 |
| 审阅与版本 | 判断矛盾和修改影响、回看历史 | 新旧版本、节点引用、事实引用 | 审阅决定、新版本或回退 | 正文、大纲和设定 |
| 导出 | 保存正文及可恢复的创作资产 | 作者确认的当前作品 | Markdown／正文包／资产 JSON | 本地文件；不自动发布 |

模型选择、任务状态、预算和数据设置是工作区辅助能力，不单独扩张为一套运营后台。

## 4. 首版 UI 覆盖

原型提供七个可切换视图。默认进入故事画布，便于直接看见产品特色；作品概览提供新手入口，章节编辑器承担高频操作。

正式版本的画布应支持拖动、缩放、连线、框选、撤销和键盘操作。**本轮原型仅展示可点击节点与结构关系，不代表这些编辑能力已经实现。**

样例作品《雾城来信》及其人物、章节和设定均为自拟内容。原型中的 AI 结果是固定示例，而非连接模型产生的输出。

## 5. 四条关键行为

### 5.1 生成是一份提议，不是覆盖保存

生成请求固定使用章节版本和设定版本。结果进入建议区；作者可以逐段接受、修改或拒绝。作者输入和旧版本在接受前保持不变。

当作者在模型返回前改动了正文，建议必须显示“基于旧版本”；不能默默套用到新正文。接受操作要检查版本冲突。

### 5.2 正文与设定双向关联，但不自动同步所有事实

正文修改可以提出新的设定候选；候选包含出处和影响范围。只有作者确认后，才进入设定库。

反向修改设定时，系统标出可能受影响的章节与情节，而不是直接重写它们。变化必须区分“确定引用关系”与“模型推测的影响”。

### 5.3 一致性反馈必须有出处

人物死亡后是否重新出现、事件先后、能力限制等规则检查可以提供确定的冲突条件。动机、节奏、文风等判断属于建议，不能包装成客观事实。

每条问题至少包含：原文位置、引用的设定、问题类型、判断理由和可采取的动作。允许作者标记“有意安排”或“不是问题”。

### 5.4 长任务可中断、失败可恢复

章节生成和全卷审阅都是独立任务。任务失败保留输入快照、已返回的片段和错误信息。重试不会重复覆盖正文或重复确认设定。

流式文字只是预览；最终持久保存必须有明确状态。关闭页面不应让任务结果丢失。

## 6. 范围取舍

**首阶段完整实现：**单人作品、多章节、故事画布、正文编辑、人物／世界／伏笔、局部生成建议、审阅确认、版本和导出。

**后续按使用反馈推进：**故事时间线专项视图、多分支剧情、跨卷检索、多人协作、移动端完整编辑。

**不纳入本产品主线：**自动投稿、自动运营读者社区、收入预测、作品质量排名、本地训练模型。对外发布必须由作者明确确认。

## 7. 内容与数据边界

- 使用原创内容或有权处理的资料，不通过抓取商业小说构建仿写素材库。
- 用户资料和正文进入外部模型前，说明传输对象与范围；日志默认不保存完整敏感正文。
- 标准版本提供可导出资产和备份路径，不把浏览器存储当可靠数据仓库。
- 对 AI 内容的出版或平台要求做独立核查；工具不承诺收入、签约或作品合规结论。

## 8. 可验证目标

不预先填写虚构指标。正式验证需留下输入集、运行版本、检查条件和失败样例。

1. 从空作品到一章可导出的正文，全程无需填完所有设定表。
2. 修改一条有明确引用的设定，可以定位引用它的章节和情节。
3. 生成失败、刷新和重试不会覆盖用户尚未确认的内容。
4. AI 提取的设定未经确认不进入事实库。
5. 正文版本、设定版本和建议来源能互相定位。
6. 用自拟或授权文本构造矛盾测试集，分别记录规则检出、模型建议和误报，不声称保证长篇绝对一致。
