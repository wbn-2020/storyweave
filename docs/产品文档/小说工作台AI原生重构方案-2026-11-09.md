## 0. 产品目标与实施边界

作者应能从一句脑洞开始，逐步获得可编辑的故事骨架，在正文、设定和大纲之间自由往返。AI 的持久产出须可查看来源、比较修改并由作者决定是否采纳；摘要和索引可以自动整理，但不得把模型推断变为作者已经确认的设定。

**数据库决策（2026-11-09 用户确认）**：本轮桌面重构采用 SQLite，工作区目录库与每本书的作品库分别保存。模型请求在写事务外执行，正式采纳核对预期版本并使用短事务；备份生成一致性快照。后续如明确开发云同步或多人服务，再按实际需求设计服务端存储与业务修订同步。

一个真正的 AI 小说家（尤其是写连载网文的作者），他的真实业务流是这样的：
1. **找感觉（拆书与吃设定）**：看到一本爆款书，想把它的开篇节奏、打斗分镜、人设反差“拆”出来变成自己的写作配方；
2. **立书（脑洞孵化 + 初版演进大纲）**：脑子里有一句爽点脑洞，让 AI 帮他变成吸引人的书名、主角金手指、核心对手，以及**管住全书不崩盘的初版三层大纲（总纲 + 第一卷主线 + 黄金三章）**；
3. **造人与织网（角色卡 + 关系画布 + 世界锻造）**：不想手填 8 个文本框，而是点一下让 AI 赋予角色“外貌辨识度、口头禅、致命弱点、六维战力”，并在画布上拉出“表面师徒、实则宿敌”的动态关系；
4. **日更码字（章纲节拍 + 仿写/润色 + 随手查设定）**：看着左边的本章 3 个节拍，在中间沉浸码字（或让 AI 按节拍扩写），选中一段话点“按某大神的冷硬文风仿写 / 去 AI 味 / 加强环境压迫感”；
5. **控盘防崩（全书记忆星图 + 伏笔雷达 + 动态修纲）**：写到第 50 章时，查看已登记出场、明确核对的连续缺席及到期伏笔；未索引章节保持未知。早期剧情改变后，由作者选定后续计划章，预览修纲差异并确认采纳。

下文覆盖八项业务，按依赖分阶段交付。默认只做静态检查；本地启动、模型请求、测试、类型检查、构建与打包分别需要明确授权。文中的延时、费用与质量目标均待真实环境验证，不作为已达到的结果。

## 2. 八大核心业务模块深度设计（作家的真实武器库）

### 业务一：一句话开书房 & 动态演进大纲（Kickstart & Living Outline）

解决痛点：**既不能让作者开局面对 5 个空框发呆，也不能一口气吐出 1 万字让作者做阅读理解，更不能只给第一章导致后面写乱。**

#### 1.1 开书包与渐进展开
作者只需输入**一句话脑洞**（或从拆书库选一个开局模板）+ 点选题材标签（如 `玄幻`、`仙侠`、`悬疑`、`赛博`），AI 一次生成**四维开书包**：
1. **书名与卖点矩阵**：5 个不同切入点的书名（爽点直给型、悬念反差型、宿命感型、轻小说型、极简型）+ 一句话故事核（Logline）+ 300 字平台级吸睛简介。
2. **核心矛盾人物组（3–4 人）**：主角（含金手指与核心执念）、开局死敌/阻碍者、核心羁绊角色（引路人或女主）。每人先出精简卡（100 字人设 + 致命弱点 + 典型台词），进书后可随时一键丰满为完整 8 维档案。
3. **世界底色与 3 条铁律**：一句话高概念 + 3 条不可违背的世界/力量规则（如“动用神通必折寿元”、“黑夜不可直视红月”）。
4. **初版三层演进大纲（控盘核心）**：
   * **全书总纲（约 400 字）**：采用作者所选的结构模板，给出故事起点、主要推进、转折与收束方向。作者可以修改或锁定其中任意目标。
   * **第一卷主线纲要（200 字）**：本卷核心目标、关底高潮（第 15-20 章要解决谁）、本卷核心伏笔。
   * **开篇三章细纲（每章节拍 + 章末悬念 + 可选紧张度分值）**。以下仅为升级流模板，悬疑、感情、日常等题材分别选用相应模板，也支持作者自定义：
     * 第 1 章：危机入局与身份困境；
     * 第 2 章：变数/金手指觉醒与首次试探；
     * 第 3 章：首轮反击打脸与新悬念抛出。

首屏优先展示书名、故事核、主角和首章冲突；总纲、配角与世界规则可展开修改。允许作者只采用部分设定后开始写作。开书包以约 1,500 字为内容预算目标，默认优先生成三章章纲；15 秒为待实测的体验目标，接口慢或输出超预算时提供进度、中止、原文留存和重试。未配置模型时仍可手工建立作品。

#### 1.2 随剧情推进不断优化完善（滚动推演 + 偏航修纲）
大纲不是死文本，而是活沙盘：
* **滚动细化（Rolling Outline）**：固定全书总纲、卷目标、当前有效的已写摘要以及相邻未写章纲，从现有大纲末尾生成后续三章提案。已有前三章时补第 4–6 章，不跳过或遗漏第 3 章计划；作者可修改范围。
* **剧情偏航修纲（Outline Rebase）**：定稿回写发现实际事件与后续章纲可能冲突时，先给出双方来源及待复核范围。作者选择章节，并明确本次锁定的总纲与卷目标；AI 生成修纲提案和逐项差异。默认只选择尚未开始写作、未锁定的章纲，作者手改内容须单独确认。采纳前再次核对章纲版本，同一事务写入新纲及不可变历史。恢复旧纲也产生新修订，保留前后版本。作者可主动解除终局目标锁定，不强制剧情回到旧结局。
* **紧张度节奏曲线**：在章纲页顶部绘制全卷 `tension (0-100)` 折线图。若连续 4 章紧张度低于 50（水字数预警）或连续 5 章高于 85（读者疲劳预警），自动在曲线上高亮提示“建议在此处插入危机转折 / 日常调剂章”。

### 业务二：拆书与仿写工坊（Book Deconstruction & Style Imitation）

解决痛点：**新手不知道怎么排布开篇节奏、怎么写打斗和拉扯；老手想提炼某位大神的文风或某本爆款的结构，但现有拆书功能藏在深处且无法直接指导写作。**

#### 2.1 三步拆书流水线（从“看爽文”到“变成我的技能卡”）
1. **喂入参考片段**：支持粘贴或导入任意小说章节/精彩片段（如一段顶尖的雨夜刺杀描写，或某个爆款的黄金第一章）。
2. **四维解剖（AI 拆书师）**：不仅提取摘录，还支持一键拆出四类结构化资产（严格保留逐字原文引文验证）：
   * **🎬 节拍骨架卡（Beat Skeleton）**：把参考章节还原为去名化的抽象动作节拍（如：`[节拍1：环境压迫开场] -> [节拍2：身份伪装被识破] -> [节拍3：利用地形反杀留活口]`），可直接**一键套用到我当前章节的章纲**！
   * **🎨 文风 DNA 卡（Style Profile）**：分析该片段的句长分布（短句爆发 vs 长句铺陈）、对白占比、感官描写偏好（视觉/听觉/痛觉）、高频动词特征，生成可挂载的**仿写文风卡**。
   * **⚔️ 技法公式卡（Technique / Method）**：提炼出具体的写作套路（如“先写围观者的轻视，再写受击者的迟缓物理反应，最后写一招秒杀的寂静”），存入全局技能库。
   * **💎 佳句与词汇包（Excerpt）**：金句、动作词库、神态词库归档。
3. **无缝反哺创作（仿写闭环）**：
   * 在写作台写正文或改写段落时，直接勾选某张**【文风 DNA 卡】**或**【技法公式卡】**，点击“按此风格扩写 / 仿写本段”。AI 只借用其句式节奏、叙事刀法与分镜结构，绝不抄袭原参考文本的人名地名与专有设定。

### 业务三：立体角色卡与试戏工坊（Character Studio）

解决痛点：**角色扁平、千人一面、名字烂大街（全是林辰、苏清雪）、写着写着性格崩坏（OOC）。**

#### 3.1 角色全生命周期工具箱
* **AI 避坑起名器**：按流派与气质（如“冷冽剑修”、“市井老油条”、“世家病弱贵公子”、“克苏鲁调查员”）生成一至四组、每组三个名字，给出创作意象，固定本书已有名字、别名和作者避用名单；典籍出处须另有可核验来源，不让模型编造。网文常见名与谐音偏好由作者要求约束模型，当前不宣称有全网重名或谐音词典。
* **8 维深度人设 + 六维能力雷达**：
  * 核心字段：`动机 (motivation)`、`眼下渴望 (desire)`、`致命弱点/盲区 (weakness)`、`高辨识度外貌与习惯动作 (appearance)`、`说话风格与口头禅 (speechStyle，附 2 句典型台词)`、`身世背景 (background)`、`成长弧光阶段 (growthStages)`、`能力与代价限制 (skillLimits)`。
  * 支持 **「✦ AI 补全空字段」**（只填空项，绝不覆盖作者手写内容）与 **「✦ 从已写正文反向提炼人物性格」**。
  * 六维数值由作者确认，范围 0–100，未填写的维度保持未知；不从文字长度推算人设或能力。正文提炼须保留固定段落逐字引文。
* **🎭 角色对话试戏舱（Character Audition / 小剧场）**：
  * 写某场重头戏前拿不准角色语气？点开角色卡上的【试戏】，输入一个情境（如：*“主角把唯一的一枚疗伤丹药扔给你，你会怎么反应？”*），AI 严格基于该角色的说话风格、当前性格与他此刻已知的信息（`cognition`）演一段对手戏，满意可直接把台词复制进正文。
* **⏱️ 角色状态时间轴（防 OOC 与防穿帮）**：
  * 同一个角色在第 1 章和第 50 章的修为、位置、伤势、持有物、心理状态、**已知秘密（Cognition）**截然不同。
  * 角色卡提供历史状态选择，同时区分故事发生时点、读者披露位置和人物获知事件。倒叙场景须显式选择故事时点，不按章节序号推断时间；角色认知还需核对主体、获知事件与有效区间。缺少时点或获知依据时显示未知，不能回退到最新全知档案。试戏与写作固定本次选定的状态快照，输出仍须由作者核对。

### 业务四：动态人物关系画布与阵营网（Relationship Canvas）

解决痛点：**人物一多关系乱成一团；表面同盟背地死敌表达不出来；画布只能看不能直接建关系。**

* **直接拖拽连线建关系**：在画布上从一个人物节点拖到另一个人物/势力节点，松手即弹出关系选择器（`师承`、`血亲`、`死敌`、`同盟`、`暗恋/情感`、`利用/背叛`、`从属`）。
* **双层关系（表面关系与隐藏事实）**：关系分别记录作者设定、读者披露位置、人物是否知情及有效故事时段。预计揭露章节是计划，不能当作已经披露或人物已经得知的证据。
* **随故事时点演变的动态关系网**：按作者明确的故事排序值筛选关系，或拖动当前页已登记时间范围，显示有效、失效或未知。章节至故事时点的映射须单独登记，不能拿章节号代替故事时间；当前源码没有自动章节时间映射。
* **AI 自动推断关系**：点击「✦ 扫描正文补全关系」，AI 从已写章节中识别人物互动，生成关系候选边，作者点一下即可确认落入画布。

### 业务五：全书记忆星图、出场矩阵与伏笔雷达（Memory Galaxy & Brain Map）

解决痛点：**写到几十万字后，作者自己都忘了前面埋过什么坑、哪个配角好久没出场、哪件道具丢在哪了。**

这不是一个花架子 3D 球，而是三个能救命的**长篇控盘视图**：

#### 5.1 视图 A：全书星海脑图（力导向关联图）
* 将全书的 **人物、地点、势力、物品、事件、伏笔** 按形状与主题色组织，提供缩放、聚焦和完整名称列表。当前按页查询，最多 40 个对象，聚焦页另含中心；120 步静态弹簧松弛只编码本页直接登记引用。
* 点击节点高亮本页直接关联，聚焦后分页读取其关联对象；来源详情可核对固定历史稿的逐字引文，再经过正文保存门禁跳到当前稿段落。图中位置不代表故事时间或语义关联强度。

#### 5.2 视图 B：章节 × 实体出场热力矩阵（长篇断档检测器）
```
实体 \ 章节   01  02  03  04  05  06  07  08   当前窗口说明
────────────────────────────────────────────────────────────────
林辰 (主角)   ●   ●   ●   ●   ●   ●   ●   ●   有已采纳事件及正文来源
苏九儿 (女主) ●   ●   ○   —   —   —   —   —   末尾连续 5 章已核对缺席
青铜古鼎      ?   ●   ●   ?   ?   ○   ?   ?   无登记处保持未知
（● 登场行动  ○ 被提及  — 明确缺席  ? 未知  ! 登记冲突  ↺ 旧稿／待复核）
```
* 每页 12 个实体 × 24 章，两方向独立翻页并固定作品和知识双版本。正向登记只汇总已采纳事件的正文来源；整章缺席由作者读取当前保存稿、指定实体和核对说明。当前正向与缺席登记并存时显示冲突。
* 连续缺席提醒只计算当前窗口末尾的明确核对结果，阈值 1–24 章，默认 10；未知或冲突中断计数。每格给出总命中数和每类一个代表记录，不根据空白格宣称全书掉线。示意表中的 5 章仅在阈值调至 5 时触发提醒。

#### 5.3 视图 C：伏笔全生命周期雷达（埋 ➔ 提 ➔ 收）
* 分离**计划回收范围**与**实际固定正文证据**。已有卷章／场景按关联位置核对；未建卷章支持明确序号，纯文字“卷末”等范围保持待定位。作者选择核对进度，卷内到期、进入后卷逾期，不把最后建章视为已写进度。
* 雷达每页 20 条，展示到期、逾期、待定位、待复核和结束状态。写作台及作者创作副驾驶显示本章提醒，换章或显式刷新时读取；作品变化后标记为上次核对结果。
* 作者明确选入后，伏笔以固定最新修订的计划资料进入 AI 发送预览，计划不等于已发生或人物知情。新确认回收或更换回收位置时，须保存同一章、修订和段落的逐字引文。

### 业务六：沉浸三栏写作台与场景节拍流水线（Chapter Studio）

解决痛点：**生成一整章太假、太水，完全失控；纯手写又容易卡壳；中间改了一段，上下文全乱。**

#### 6.1 两种写作模式无缝切换
* **模式一：AI 节拍扩写流水线（适合快速出初稿）**
  1. **看上下文清单（100% 透明）**：生成前明确列出本次携带的弹药：`[创作宪章 3 条] + [前情摘要 3 章] + [在场角色：林辰、赵执事（含当前伤势与说话风格）] + [待埋伏笔 1 条] + [挂载技能：打斗动作分解 + 去 AI 味]`，作者可随时勾选增删。
  2. **确认本章 3 节拍**：先看/微调本章的 3 个场景节拍（如：场 1 夜市试探 ➔ 场 2 暗巷交手 ➔ 场 3 发现密信）。
  3. **按节拍流式生成或整章生成**：可以一段一段推进（写完场 1 满意再写场 2，永不跑偏），也可以一键连写全章。
* **模式二：选中即改 / 局部精修（适合人机共创）**
  * 在正文中框选任意几段话，呼出快捷指令条：
    * `✨ 去 AI 味润色`（洗掉“嘴角勾起一抹弧度、眼中闪过一丝精芒”，换成具体动作与生理反应）
    * `⚔️ 扩写动作/环境细节`
    * `💬 强化对白潜台词（贴合角色口癖）`
    * `🎭 按指定文风 DNA 仿写`
  * **定点替换 + 段落 Diff 对比**：只改选中的这几段，前后文纹丝不动；修改前后并排高亮对比，可一键采纳或随时退回原段。

### 业务七：审稿、去 AI 味与多维读者模拟（Review & Reader Simulation）

解决痛点：**写完一章心里没底，不知道爽点够不够、有没有跟前文设定冲突、AI 味重不重。**

**取消一切“不达标禁止定稿”的霸道门禁！** 改为给作者赋能的三大审稿助手：
1. **🔍 事实与连贯性核查（抓硬伤）**：对照知识库与人物当前认知，专门抓“人物出现在不该出现的地方”、“使用了尚未获得的道具”、“提前知道了未揭晓的秘密”、“违背世界铁律”。每条问题必须给出冲突双方证据。
2. **语言与句式提示**：本地固定套话词表扫描和同一段中连续相同代词句首提示，列出实际段落、片段与固定修订。命中不是 AI 来源或质量证明；当前不输出困惑度、AI 概率、过审分数或说明文语义占比。需要润色时先明确发送审稿请求，再逐项比较替换稿并确认采用。
3. **👥 三维虚拟读者试读间（网文特色利器）**：
   * 让三个不同口味的虚拟读者读完本章并给出弹幕式锐评：
     * **【爽点党/小白读者】**：只关心“这章憋不憋屈？节奏拖不拖？章末钩子想不想点下一章？”
     * **【设定考据党/老书虫】**：专门挑刺“战力合不合理？反派是不是强行降智？逻辑有没有漏洞？”
     * **【情绪共鸣/CP 党】**：评价“人物互动甜不甜/虐不虐？人设有没有立住？台词尴不尴尬？”
   * 吐槽提供【定位并生成定点改写提案】，作者查看差异后采纳。虚拟读者意见是模型建议，不以多个角色一致作为真实性证明，不承诺固定时间修好。

### 业务八：AI 模型路由中心（Multi-Model Hub）

解决痛点：**每建一本书都要重新配一次 API Key；不同任务其实适合用不同模型（推理模型适合排大纲，文笔好的模型适合写正文，便宜快速的模型适合抽摘要）。**

* **工作区级全局连接池（配一次，全书通用）**：
  * 首版连接使用 OpenAI 兼容的 Chat Completions 文本接口；提供方须实际支持该协议。其他协议和特性按适配器单独验收，不以厂商名称推断兼容。
  * 密钥仅保存在当前桌面进程的会话内存，不进入作品库、日志、快照、恢复包或浏览器存储。重启后重新输入；连接配置和默认选择仍保存于工作区。新作品复用工作区连接，允许一次任务显式覆盖。
* **按任务智能分流（Task Routing，可选高级功能）**：
  * 允许作者为不同工种指定最擅长的模型：
     * 规划、续写、改写、审稿和拆书各选一个默认预设，可绑定本书模型连接；在副驾驶明确载入要求与模型，实际发送前再次确认固定预览。
     * 演进沙盘、角色工坊及独立整理任务继续显式选择模型；跨所有专用工种的工作区自动分流留待后续设计。
     * 累计用量合并开书与书内协作，未知输入、输出分别计数；尚无单价配置和费用核算，不用估算值填补实际用量。
* **透明 Token 账单**：每次生成前预估输入 Token，生成后记录实际消耗。

## 3. 核心业务规则与提交边界

以下规则约束各阶段的契约、存储和界面。数据结构与 API 均需覆盖对应正常、冲突和恢复分支；写出设计不等于已实现或已验收。

### 3.1 孵化作品与恢复
* 首次提交脑洞时固定 `draftId` / `bookId`，建立 `lifecycle = 'kickstarting'` 的作品。重复请求使用同一身份；单纯打开页面不创建空资产。重新进入可选择继续已有草稿。
* `book.sqlite` 是作品内容依据，工作区书架仅为可修复目录。库初始化后再登记目录；登记失败保留完整书库，并提供扫描预览与补登记。空文件或未完成初始化的文件只报告，不自动删除或覆盖。
* 开书提案、选用状态和最终书名、总纲、卷章、设定都落在同一作品库。最终采纳用一个事务核对提案与作品版本、登记采纳回执并激活作品。重复采纳返回原回执，不能重复建章。
* 启动时将没有存活会话的 `running` 任务转为中断终态，保留已接收输出。恢复显示持久提案和已完成步骤；重新请求模型是新尝试，不承诺网络流从字节断点继续。未知写入先核对原请求与采纳回执。

### 3.2 候选版本、逐项选用与采纳
* **独立候选状态**：`generation_runs.proposal_json` 中的每一个候选条目（每个书名、每个角色、每条世界规则、每章细纲）都带有稳定 UUID `candidateId` 和独立状态 `status: 'pending' | 'adopted' | 'discarded'`。支持先采纳主角，保留配角待定，或单独重掷某一张卡。
* **稳定身份**：槽位表示叙事职责，实体 ID 表示具体人物。每次重生成建立新候选和父提案引用，保留原输出与候选历史。换人物与改名分开处理，不能用字符串替换推断动机、能力与人物关系仍成立。
* **开书选用**：孵化期间的书名、角色和规则可独立选择或取消，持久保存选择版本；最终开书事务才统一写入选中内容。作者可只选主角与首章所需设定，其余候选继续保留。
* **正式作品采纳**：回执固定 `adoptionId + candidateId + entityId + resultingRevisionId`。创建或更新实体、候选终态和回执在同一事务内写入，并核对预期版本；重复请求返回同一回执。已采用候选不可原地改写，后续改动产生新提案。
* **依赖复核**：候选和章纲记录引用的实体及修订。换角色或修改规则后，受影响的未来章纲标为 `stale`，经比较确认后修纲；已写正文仅提示待复核，不自动替换。

### 3.3 五域健康度与非线性创作
* 废除单向锁死的 `book_meta.stage` 枚举。五个脊椎节点（`脑洞 · 世界 · 角色 · 大纲 · 正文`）任何时候均可自由点击进入，支持“先写正文再补设定”或“写到第 20 章回头改世界观”。
* 每个脊椎节点的状态由当前数据库实时聚合计算：
  * `empty`（尚未建立）
  * `pending_proposal`（有未处理的 AI 提案）
  * `stale`（上游设定已变更，本域存在待复核条目，例如改了力量法则后相关章纲标黄）
  * `ready`（已就绪）

### 3.4 定稿整理、派生依赖与发布
* **如何区分客观事实与角色谎言**：定稿抽取 Prompt 强制为每条提取物打上现有 `KnowledgeNature` 标签：正文明确发生的记为 `narrative_claim`，角色口头说的或猜测的记为 `character_belief`，AI 归纳的记为 `ai_derived`。
* **不污染正史的“一键确认抽屉”**：
  * **本章节摘要（Summary）与出场索引**：直接绑定 `chapterId + revisionId` 保存，不修改全局设定。
  * **涉及新增/修改角色状态、新伏笔、新地点**：定稿后在右侧弹出非阻断的【本章记忆归档卡】（默认勾选高置信度条目，作者扫一眼点“确认归档”即入库，发现把反派假话当真的点一下即可剔除或改为 `character_belief`）。
* **原子发布**：先在数据库事务外完成模型抽取和引文验证，再核对当前定稿修订及依赖版本；通过后在同一事务发布新整理批次、推进有效批次指针并将旧批次标为 `superseded`。同一章节修订与整理类型重复提交返回原发布结果。失败或中断保留提案，显示“待整理”；不把上一版记忆标成已追平新稿。
* **依赖失效**：每项摘要、事件与状态快照除直接正文来源外，还保存本次用到的事实、实体修订或摘要批次。来源变化后，将依赖该来源的后续派生产物标为 `stale` 并传播到其依赖者；上下文只选择当前有效且依赖完整的产物。作者锁定内容保留并进入冲突待裁决，不自动撤销或覆写。
* **历史认知**：人物获知、读者披露和故事发生时间独立存储，未知即未知。章节顺序用于导航与阅读范围，不替代故事时间或获知证据。

### 3.5 正文编辑与局部改写
* **唯一口径**：保留现有 `ManuscriptDocument` 的段落 `blockId` 结构（因为拆书引文核对、记忆出处定位、审稿问题定位、段落级 Diff 改写全部建立在稳定的 `blockId` 之上），不换成裸 `textarea`。
* **体验升级**：在 UI 层彻底隐藏富文本格式噪音，提供纯文本级的行云流水输入体验、段首自动缩进、字数/码字速度实时统计，以及**选中段落即浮现 AI 改写/仿写工具条**。

### 3.6 连接选择与可追溯输入

连接按“本次显式选择 → 对应任务的工作区默认 → 工作区通用默认”解析，同一任务只能有一个默认连接。删除或修改连接不改变历史任务。每次运行固定不含密钥的连接快照（端点、模型、配置版本、输入窗口、输出预算）、提示版本、实际 messages、依赖修订与输入指纹。该快照用于审阅和重发相同输入，不承诺重新生成相同输出。

### 3.7 实施与验证

按现有工作树逐文件修改，保留任务外未提交内容。使用现有标准库与依赖，不安装新依赖；不新增或改写单元测试。文档完善和源码施工已获用户授权，不依赖外部工作流。默认使用源码阅读、差异检查、契约及路径核对；需要运行项目的检查明确记录为待授权验收，不能把静态检查表述为运行通过。

## 4. 核心数据契约与表结构蓝图

新建作品目标为 book v15、工作区目标为 v3。下列 SQL 展示目标字段，实际新增结构和版本支持边界以源码与开发进度记录为准。施工不打开、删除或自动改写真实书库；发现旧格式时提示实际支持范围，不因文档声称无存量就覆盖现有文件。

```sql
-- ============================================================
-- 1. 工作区库（studio.sqlite，STUDIO_SCHEMA_VERSION = 3）
-- ============================================================

-- 工作区全局 AI 连接池（配一次，所有新书与拆书直接可用）
CREATE TABLE studio_ai_connections (
  id TEXT PRIMARY KEY,
  version INTEGER NOT NULL DEFAULT 1 CHECK (version >= 1),
  name TEXT NOT NULL,
  provider TEXT NOT NULL DEFAULT 'openai_compatible',
  base_url TEXT NOT NULL,
  model TEXT NOT NULL,
  context_window INTEGER NOT NULL CHECK (context_window >= 1024),
  max_output_tokens INTEGER NOT NULL CHECK (max_output_tokens > 0 AND max_output_tokens < context_window),
  is_default INTEGER NOT NULL DEFAULT 0 CHECK (is_default IN (0, 1)),
  -- 按任务路由默认标记：可为 outline / draft / review / extract 指定不同默认连接
  task_routes_json TEXT NOT NULL DEFAULT '[]',
  updated_at TEXT NOT NULL
) STRICT;
CREATE UNIQUE INDEX one_default_studio_connection ON studio_ai_connections(is_default) WHERE is_default = 1;

-- ============================================================
-- 2. 书籍库（book.sqlite，BOOK_SCHEMA_VERSION = 15）
-- ============================================================

-- 作品元数据（含孵化状态、故事核与全书总纲）
CREATE TABLE book_meta (
  singleton INTEGER PRIMARY KEY CHECK (singleton = 1),
  id TEXT NOT NULL UNIQUE,
  title TEXT NOT NULL,
  genre TEXT NOT NULL DEFAULT '',
  -- lifecycle: kickstarting(开书孵化中) | active(连载创作中) | finished(已完结)
  lifecycle TEXT NOT NULL DEFAULT 'active' CHECK (lifecycle IN ('kickstarting', 'active', 'finished')),
  logline TEXT NOT NULL DEFAULT '',
  synopsis TEXT NOT NULL DEFAULT '',
  -- 全书四幕总纲与核心卖点 JSON（起承转合、主线终局目标、平台买点）
  master_outline_json TEXT NOT NULL DEFAULT '{}',
  seed_json TEXT NOT NULL DEFAULT '{}',
  target_chapters INTEGER CHECK (target_chapters IS NULL OR target_chapters > 0),
  target_words_per_chapter INTEGER CHECK (target_words_per_chapter IS NULL OR target_words_per_chapter > 0),
  cover_style TEXT NOT NULL DEFAULT 'ink',
  archived_at TEXT,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  revision INTEGER NOT NULL DEFAULT 0 CHECK (revision >= 0),
  knowledge_revision INTEGER NOT NULL DEFAULT 0 CHECK (knowledge_revision >= 0),
  index_publication_version INTEGER NOT NULL DEFAULT 0 CHECK (index_publication_version >= 0)
) STRICT;

-- 分卷表（扩充卷级主线目标、本卷高潮与冲突）
CREATE TABLE volumes (
  id TEXT PRIMARY KEY,
  title TEXT NOT NULL,
  position INTEGER NOT NULL UNIQUE CHECK (position >= 0),
  goal TEXT NOT NULL DEFAULT '',
  conflict TEXT NOT NULL DEFAULT '',
  climax TEXT NOT NULL DEFAULT '',
  volume_summary TEXT NOT NULL DEFAULT '',
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
) STRICT;

-- 章节表（扩充冲突、章末钩子、紧张度 0-100、结构化节拍 beats_json、大纲偏航标记）
CREATE TABLE chapters (
  id TEXT PRIMARY KEY,
  title TEXT NOT NULL,
  position INTEGER NOT NULL UNIQUE CHECK (position >= 0),
  volume_id TEXT REFERENCES volumes(id) ON DELETE SET NULL,
  goal TEXT NOT NULL DEFAULT '',
  conflict TEXT NOT NULL DEFAULT '',
  hook TEXT NOT NULL DEFAULT '',
  tension INTEGER CHECK (tension IS NULL OR (tension >= 0 AND tension <= 100)),
  -- 结构化节拍数组：[{ id, title, action, outcome, status }]
  beats_json TEXT NOT NULL DEFAULT '[]',
  -- 上游世界观/人物大改或前章剧情分叉时标记为 1，提醒作者一键修纲
  outline_stale INTEGER NOT NULL DEFAULT 0 CHECK (outline_stale IN (0, 1)),
  viewpoint TEXT NOT NULL DEFAULT '',
  target_characters INTEGER,
  notes TEXT NOT NULL DEFAULT '',
  status TEXT NOT NULL DEFAULT 'planned' CHECK (status IN ('planned', 'writing', 'review', 'finalized')),
  current_revision_id TEXT NOT NULL,
  finalized_revision_id TEXT,
  finalized_at TEXT,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  FOREIGN KEY (id, current_revision_id) REFERENCES chapter_revisions(chapter_id, id) DEFERRABLE INITIALLY DEFERRED,
  FOREIGN KEY (id, finalized_revision_id) REFERENCES chapter_revisions(chapter_id, id) DEFERRABLE INITIALLY DEFERRED
) STRICT;

-- 书级 AI 生成运行表（开书包、世界锻造、角色班底、动态大纲推演与修纲）
-- 完整保留连接快照、prompt_version 与 messages_json；重新请求模型不保证复现同一输出
CREATE TABLE generation_runs (
  sequence INTEGER PRIMARY KEY,
  id TEXT NOT NULL UNIQUE,
  book_id TEXT NOT NULL REFERENCES book_meta(id),
  kind TEXT NOT NULL CHECK (kind IN ('kickstart', 'world', 'cast', 'outline_expand', 'outline_rebase')),
  state TEXT NOT NULL CHECK (state IN ('prepared', 'running', 'succeeded', 'failed', 'cancelled', 'discarded')),
  version INTEGER NOT NULL DEFAULT 1 CHECK (version >= 1),
  connection_id TEXT NOT NULL,
  connection_name TEXT NOT NULL,
  model TEXT NOT NULL,
  -- 不含密钥的端点、配置版本、预算与请求参数快照
  connection_snapshot_json TEXT NOT NULL,
  parent_run_id TEXT REFERENCES generation_runs(id),
  prompt_version INTEGER NOT NULL,
  instruction TEXT NOT NULL,
  seed_json TEXT NOT NULL,
  messages_json TEXT NOT NULL,
  context_hash TEXT NOT NULL,
  -- 含每个 candidateId 的独立状态（pending / adopted / discarded）与 slot 槽位
  proposal_json TEXT NOT NULL DEFAULT '{}',
  -- 孵化期独立选择及已采纳目标；通过 version 条件写入
  selection_json TEXT NOT NULL DEFAULT '[]',
  adopted_refs_json TEXT NOT NULL DEFAULT '[]',
  output_text TEXT NOT NULL DEFAULT '',
  usage_json TEXT,
  book_revision INTEGER NOT NULL CHECK (book_revision >= 0),
  knowledge_revision INTEGER NOT NULL CHECK (knowledge_revision >= 0),
  error TEXT,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
) STRICT;
CREATE INDEX generation_runs_recent ON generation_runs(book_id, sequence DESC);
CREATE UNIQUE INDEX one_running_generation_per_book ON generation_runs(book_id) WHERE state = 'running';
```

M1 的实际源码以 `part` 区分完整开书、书名、人物、规则与大纲；运行状态含 `interrupted`，采用回执独立保存在 `generation_adoptions`，不以运行状态代替各候选的采用决定。上述 SQL 仍是后续扩展蓝图，不能直接用作当前库的建表或升级脚本。

M2 已追加不可变章纲修订、整理批次及发布指针、派生依赖和失效计算，见[v16 数据说明](../技术架构/演进大纲与记忆发布-2026-11-10.md)。M3 追加工坊固定请求、采用回执、可选六维能力与关系层次，见[v17 数据说明](../技术架构/角色工坊与历史状态-2026-11-10.md)。JSON 字段须有严格解析、数量与字节上限，不能仅凭字符串有效就接受；各阶段分别记录恢复包兼容和运行验收边界。
