## 2. 原调研是否合理

### 2.1 值得保留的判断

1. 以作者显式选择、发送、审阅、采用为核心，比扩大模型自治范围更符合当前资产与版本设计。固定上下文、不可变历史、引文和采用审计都有对应源码。
2. 区分正文事实、计划、人物认知、AI 推断和外部参考有实际价值；“有引文”“已采用”“来源未过期”分别回答不同问题。
3. 人物当前认知加形成时间不能重建完整历史心智；长上下文窗口也不能直接证明长篇召回和时点一致性。
4. 先补章场衔接、目的明确的改稿、实体消歧和版本比较，属于合理产品建议。是否改善零经验作者表现，仍需用户研究或交互验收。
5. 现有 SQLite、独立业务进程、分批处理可以继续作为实现基础；没有足够证据要求立即引入图数据库、常驻模型服务或新的重型基础设施。

原文自己声明它是研究与设计评审，不是已批准的实施方案；这一定位正确。原文的“高／中”建议优先级也不等于本报告的 P1／P2 代码严重度。

## 3. 确认的问题及证据链

### SR-01｜P1｜异常 UTF-16 正文在提交后产生不一致历史

**位置：** [manuscript.ts:85](../../src/contracts/manuscript.ts#L85)、[studio-repository.ts:381](../../src/infrastructure/storage/studio-repository.ts#L381)、[studio-repository.ts:404](../../src/infrastructure/storage/studio-repository.ts#L404)、[studio-repository.ts:214](../../src/infrastructure/storage/studio-repository.ts#L214)、[book-recovery-repository.ts:349](../../src/infrastructure/storage/book-recovery-repository.ts#L349)。

**触发条件：** 正文 text 节点含未配对 UTF-16 代理字符，例如 JSON 中的 `"text":"\ud800"`。这不是正常汉字或完整 emoji；有效结构的 JSON 草稿可携带该输入，其他身份及版本字段须有效。

**静态链路：**

1. `parseManuscript()` 校验节点、长度、marks 等，没有拒绝未配对代理字符。草稿中 document 与 plainText 若使用相同异常字符，一致性比较也能通过。
2. 保存将同一正文分别变为 `JSON.stringify(document)` 和 plainText。JSON 表示保留转义形式，而原生 SQLite 字符串绑定需要 UTF-8。
3. 精确依赖源码显示：better-sqlite3 13.0.3 的 `src/util/data.cpp` 使用 `Napi::String::Utf8Value()` 后调用 `sqlite3_bind_text`；node-addon-api 的该方法调用 `napi_get_value_string_utf8`。Electron 45.2.2 的 DEPS 指向 Node 24.22.2，该接口经 `WriteUtf8V2` 使用 `kReplaceInvalidUtf8`，把孤立代理字符替换成 U+FFFD。公开源码证据见第 7 节。
4. 因此 document_json 解码得到原代理字符，plain_text 读回得到替换字符。正文保存的 `.immediate()` 在第 404 行完成，随后第 407 行回读；第 218 行发现不一致并抛出 `STORAGE_ERROR`，此时普通保存事务已提交。
5. JSON 草稿导入同样在 [studio-repository.ts:751](../../src/infrastructure/storage/studio-repository.ts#L751) 写入、第 754 行提交、第 756 行回读。历史有不可变触发器；完整恢复包逐一校验所有历史正文，故该不一致历史会阻止导出。

**影响与边界：** 调用显示失败但不一致修订已经成为当前指针；正常读取该修订失败。仓储的恢复入口可以用健康旧版本产生新的正常当前稿，但本轮未验证异常状态下的 UI 可达性；保留的不一致历史仍会阻止完整恢复包。原 JSON 与其他健康历史仍在，不能称为原文全部不可恢复。AI 采用有外层事务，不能把上述“提交后失败”不加区分地推广到该路径。本轮未构造或导入异常文件，也未写任何数据库。

**最小建议：** 正文契约统一拒绝不能无损编码的 UTF-16 字符串，并在事务提交前完成存储表示一致性校验。已有异常历史须另行设计保留原始资产的修复流程，不应直接删改不可变历史。

### SR-02｜P2｜资料表单编辑绕过关窗保护

**位置：** [EditingDialogs.tsx:6](../../src/renderer/components/EditingDialogs.tsx#L6)、[EditingDialogs.tsx:22](../../src/renderer/components/EditingDialogs.tsx#L22)、[App.tsx:646](../../src/renderer/App.tsx#L646)、[App.tsx:735](../../src/renderer/App.tsx#L735)、[useChapterSession.ts:48](../../src/renderer/hooks/useChapterSession.ts#L48)。

**触发条件：** 打开作品或章节资料，修改简介、目标、视角或备注但未提交；正文已保存，且没有其他活动请求或脏面板。

**静态链路：** 资料仅保存在组件局部 `useState`；公共接口及 App 接线均无 dirty 回调。App 的关窗门禁识别其他面板状态后调用正文 `flush()`，正文干净时直接返回 true。主进程收到允许关闭并成功关闭服务后销毁窗口，局部输入随之消失。

**反证与边界：** 原生 `dialog.showModal()` 只限制页面内交互，不能阻止窗口关闭。已有正文保护和活动请求检查不涵盖未提交的表单字段；不是正文自动保存本身失效。

**最小建议：** 按实际字段差异上报资料表单脏状态，纳入关窗与对话框关闭流程，提供保存、放弃、取消选择。

### SR-03｜P2｜旧拒绝确认使用后来候选的身份

**位置：** [AiPanel.tsx:225](../../src/renderer/components/AiPanel.tsx#L225)、[AiPanel.tsx:350](../../src/renderer/components/AiPanel.tsx#L350)、[AiPanel.tsx:789](../../src/renderer/components/AiPanel.tsx#L789)、[AiPanel.tsx:838](../../src/renderer/components/AiPanel.tsx#L838)、[AiPanel.tsx:994](../../src/renderer/components/AiPanel.tsx#L994)。

### SR-04｜P2｜finish 尚未提交就被拒绝，最终模型数据失去恢复路径
